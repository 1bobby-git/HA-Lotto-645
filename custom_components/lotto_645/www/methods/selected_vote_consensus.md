# 합의 추천 · 계열별 다수결

[추첨 공식 목록](../../README.md#추첨-공식-22종) · [공통 계산 원리](../FORMULAS.md)

`method_id: selected_vote_consensus` · 후보 풀: **0개**

## 계산 원리

선택한 다른 로컬 공식의 실제 추천번호에 표를 줍니다. 균등 엔진은 같은 계열, 가중 빈도·핫넘버·지수감쇠·베이지안은 같은 계열로 묶습니다. 같은 계열에서 k개 공식이 참여하면 각 공식은 자기 번호에 1/k표를 줍니다. 나머지는 각각 독립 계열입니다. 표는 유리수로 정확히 합산합니다.

번호별 표 합이 큰 6개를 선택합니다. 동일 조합이 과거 1등·다른 추천과 겹치면 내림차순 후보 탐색으로 다음 최대 득표 허용 조합을 선택합니다. 득표 동점은 입력 추천 서명과 번호의 SHA-256 순서로 결정하므로 같은 입력은 안정적으로 유지됩니다. 사용자가 선택한 원본이나 번호가 바뀌면 자동 갱신합니다.

중앙값 합의·자기 자신·AI는 투표에서 제외합니다. 유효한 다른 로컬 공식이 최소 2개 필요하며 득표한 번호만 사용합니다. 모든 허용 후보가 없으면 생성 불가를 표시합니다. 기존 `selected_median_consensus`의 의미와 기록을 바꾸지 않기 위해 별도 선택 ID를 사용하며 기본 활성화하지 않습니다.

## 계산 예시

같은 균등 계열 A와 B가 각각 번호 7을 선택하면 A 0.5표 + B 0.5표 = 1표입니다. 독립 계열 C도 7을 선택하면 합계 2표가 됩니다. 균등 구현을 여러 개 선택했다고 한 계열의 영향이 그 개수만큼 증가하지 않습니다. 다수결은 새로운 예측 정보가 아니며 득표가 당첨 확률은 아닙니다.

## 설정·센서

추천 설정에서 **계열별 다수결**과 다른 로컬 공식 2개 이상을 선택합니다. `consensus_source_numbers`, `consensus_family_count`, `consensus_number_votes`, `consensus_input_signature`가 근거입니다. 원본 부족 시 센서는 번호 대신 대기 상태와 사유를 표시합니다. 점수는 null입니다.
