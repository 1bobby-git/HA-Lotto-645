# 추첨 공식 설명 · 단일 스크롤 · 추첨 카운트다운

## v1.11.8 사용 방법

추천 리뷰의 **이번 추첨, 추천번호 결과**와 **공식별 누적 리뷰**에서 파란 점선 밑줄이 있는 공식 이름을 누른다. 상세 설명 팝업에서 사용하는 데이터, 계산 원리, 가중치, 가상 예시, 설정과 해석의 한계를 확인할 수 있다. Escape 또는 닫기 버튼으로 닫으면 누르던 공식으로 초점이 돌아간다.

기존 `docs/methods/` 23개 문서의 원본 바이트를 `custom_components/lotto_645/www/methods/`에 함께 배포한다. HACS가 통합 폴더만 설치해도 설명이 동작한다. AI 설명은 [별도 문서](AI_RECOMMENDATION.md)이며 로컬 23종에 합산하지 않는다. 안내를 열어도 추천을 재생성하거나 AI에 요청하지 않는다.

문서는 처음 여는 공식만 **사용자 HA의 로컬 정적 경로**에서 읽고 이후에는 메모리 캐시를 이용한다. 이미지 업로드, 외부 글꼴/파서/CDN 요청은 없다. 원문 링크를 사용자가 클릭하면 현재 설치 버전의 GitHub 문서가 새 탭으로 열린다. Markdown의 HTML은 실행하지 않고 문자로 표시하며 실행 가능한 URL은 링크로 만들지 않는다. 문서 로딩에 실패하면 재시도와 원문 링크를 제공한다.

## 스크롤

로또 custom element를 HA가 제공한 위치 지정 패널 영역 안에 제한한다. 기존 `min-height:100%`와 inline custom-panel 래퍼가 바깥 문서까지 늘어나게 하지 않는다. 페이지의 세로 스크롤 소유자는 로또 패널 하나이며 표는 높이 제한 없이 흐른다. 좁은 표에서 번호는 필요한 경우 줄바꿈한다.

설명 팝업과 복권 등록창은 본문만 스크롤하고 배경 패널은 잠근다. HA 자체 사이드바의 독립 스크롤은 정상이며 제거하지 않는다. 부모 HA DOM/Shadow DOM이나 전역 document 스크롤 스타일을 수정하지 않는다.

## 회차별 정규 추첨 카운트다운

동행복권 [당첨자 가이드](https://www.dhlottery.co.kr/guide/wnrGuide)는 로또 추첨방송을 **매주 토요일 오후 8시 35분경**으로 안내한다(개발 시 2026-09-14 확인). [MBC 방송 안내](https://program.imbc.com/lotto)도 화면에서 열 수 있다.

HA 서버의 한국시간과 정규 주간 회차를 기준으로 예정 시각을 계산한다. 브라우저는 일·시간·분·초만 갱신하고 매초 서버나 복권 사이트를 조회하지 않는다. 화면 비활성화·페이지 이탈 시 타이머를 중단한다. 회차 1의 날짜는 기존 검증 이력의 2002-12-07이다.

- 토요일 예정 시각 전: 남은 시간 표시.
- 예정 시각 이후 결과 미수신: 음수나 가짜 당첨 결과 대신 `추첨 예정 시각이 지났어요` 및 결과 확인 대기 표시.
- 해당 토요일 결과 수신: 다음 회차 일정 표시. 다음 날이 되어도 지난 회차 수신에 묶이지 않는다.
- 앱 복귀: 현재 시각에서 남은 시간을 다시 계산. 기존 v1.11.5의 상태 동기화 정책은 그대로 유지.

**이는 정규 일정 기준의 예정 카운트다운이다. 회차별 방송 편성 변경·지연을 자동 수집하거나 확정 방송시각이라고 주장하지 않는다.** 화면에도 이 제한을 표시한다. 결과 도착, 번호 생성, 복권 구매 마감과 카운트다운을 혼동하지 않는다. 기존 추천/AI/센서 ID/저장/revision/결과 대조를 변경하지 않는다.

## 검증 범위

`tests/test_panel_metadata.py`: 정규 회차, KST/UTC, 토요일 발표 전후, 일요일 전환, 입력 날짜 검증, 23개 문서 원본과 번들 일치, AI 문서 분리, 진입 모듈 버전 검사.

`scripts/smoke_ticket_panel.py`: 기존 QR·저장·초안·디자인·safe-area 검사를 유지하고 `smoke_panel_tools.py`를 실행한다. 실제 배포 모듈에서 18개 설명, 양쪽 표의 클릭, 로딩 오류/재시도/캐시, 초점 순환·복귀, Markdown 안전 처리, 7개 할당 viewport의 단일 스크롤, 팝업 safe-area, 마감 전후/다음 회차, 타이머의 WebSocket 요청 없음과 해제를 검증한다.

브라우저 테스트의 HA 응답과 할당 viewport는 fixture다. 실제 사용자 HA와 물리 iPhone/Safari 검증은 별도다.
