## 원문 그대로 사용하지 않은 항목

### 일진 기준일 오류

원문 1.2.11은 1900-01-01과 2000-01-01을 모두 갑진일로 지정한다. 두 날짜는 36,524일 차이이며 60으로 나눈 나머지는 44다. 따라서 동시에 성립하지 않는다. 아래 표는 `lunar_python 1.4.8`과 독립 구현인 `korean_lunar_calendar 0.3.1`의 일진을 비교한 테스트 fixture다.

| 날짜 | 원문 | 적용·독립 검산 |
|---|---|---|
| 1900-01-01 | 갑진 | 갑술 甲戌 |
| 2000-01-01 | 갑진 | 무오 戊午 |
| 2020-01-01 | 정사 | 계묘 癸卯 |
| 2025-01-01 | 임진 | 경오 庚午 |
| 2026-01-01 | 정유 | 을해 乙亥 |

고정된 2026-01-06, 연도별 간이 절입일표, 근사 음양력 덧셈 및 잘못된 예시 일주는 계산의 기준으로 사용하지 않는다. 실제 데이터의 다음 회차 예정일을 사용하며, 날짜가 없으면 오늘로 추정하지 않고 계산을 중단한다.

### 지장간·십신의 충돌 및 학파 선택

- 원문 1.2.9의 **亥 = 戊23%·甲17%·壬60%**를 이번 모델의 선택 규칙으로 사용한다. 라이브러리의 일반 지장간 목록과 차이가 있으며 보편적인 유일 표준이라고 주장하지 않는다.
- 원문 지지 십신 조견표 일부는 정기·지장간 및 생극·음양 규칙과 일치하지 않는다. 예: 갑 일간의 巳 정기 丙은 식신이지만 지지 조견표에는 상관으로 기재되어 있다. **천간 십신 규칙 + 지장간 정기**를 기준으로 통일하고 원문의 충돌을 기록한다.
- 午未 합화 오행은 원문부터 화/토로 병기되어 있어 특정 오행으로 자동 변환하지 않는다. 모든 합은 관계의 존재만 판별하며 **합화 성립은 확정하지 않는다**.
- 억부·조후·통관·병약은 서로 다른 보완 후보를 낼 수 있다. 결과는 `용신 확정`이 아니라 **보완오행 후보**다. 종격·화격에 대한 조건이 부족하므로 임의의 정통 판정을 만들지 않는다.

## 달력과 시각

음력 입력은 한국 음력 변환기를 오프라인으로 사용한다. 지원 출생연도는 1900~2050이며 미래 출생일은 거절한다. 유효한 음력 2월30일을 양력 2월30일로 오인하지 않는다. 존재하지 않는 윤달은 변환기 반환값뿐 아니라 실제 윤달 플래그까지 확인한다.

한국과 중국 음력은 날짜·윤달이 다른 경우가 있다. v1.5.5에서 중국 음력 변환에 의존했던 입력은 v1.6.0의 한국 음력 기준으로 결과가 달라질 수 있으므로 **음력 입력 사용자에게 재확인을 권장**한다. 해외 출생은 입력 시간대의 민간시각을 사용하지만 음력 달력 자체는 한국 기준이다. 중국 음력을 사용하는 사용자는 확정한 양력 날짜로 입력한다.

연·월주는 출생 절대시각을 UTC+8의 라이브러리 절기 시각과 비교해 구한다. 일·시주는 출생지 민간시각 또는 명시적으로 선택한 진태양시로 구한다. 진태양시 보정으로 출생의 절대시각이나 절입 시점까지 바꾸지 않는다. 서머타임 결손/중복 시각은 임의 선택하지 않고 오류로 안내한다. 경도 NaN/무한대도 거절한다.

진태양시 균시차는 근사식이므로 경계 수분 이내의 시각은 추가 검산 대상이다. 다음 로또 회차의 **20:35 Asia/Seoul은 계산용 예정시각 가정**이며 실제 추첨 시각을 검증했다는 뜻이 아니다.

대운은 원문의 `절(Jie)까지 일수÷3 → 0.5 올림한 정수 나이` 방식을 선택했다. 정밀 분초 환산 기산법과 같다고 주장하지 않는다. 기산 절기·시간대·일수·반올림 전 나이·대운별 실제 경계 날짜를 공개한다. 생일이 2월29일이면 경계일은 2월28일로 두는 응용 정책을 표시한다.

## 자체 계량 규칙 — 전통 표준값이 아님

- 오행량: 천간 각1, 지지는 지장간 비율 합계1로 평가한다. 월지 총량1.5는 자체 가중치이며 지지 오행1을 더해 이중 계산하지 않는다.
- 강약 지수: `.45×비겁·인성 지지비율 + .25×월지 지원 + .20×통근비율 + .10×투출 천간 지원`. 0.40 이하 신약, 0.60 이상 신강, 그 사이는 중화. **원문의 정량 임계값이 아니며 학파별 전문가 판단을 대체하지 않는다.**
- 보완 후보: 억부/조후/통관/병약을 별도로 제시한다. 통관의 동시 편중 기준0.24, 병약의 과다 기준0.40, 각 이론의 가중치는 개발자 응용이다.
- 번호 오행: `끝자리`로 1~45를 하도에 반복 배속한다. 홀수=양/짝수=음으로 가상 천간을 구성해 일간과의 십신10종을 구한다. **로또 번호가 원래 천간이라는 주장이 아니다.**
- 번호 점수: 보완오행 합의55% + 십신10종 분포20% + 운별 적합도25%. 숫자에 유리한 '편재=당첨' 같은 공식을 만들지 않는다.
- 운별 비중: 대운30%·세운25%·월운20%·일진15%·시진10%. 대운 전이면 없는 층은 제외하고 나머지를 정규화한다.
- 관계 효과: 해당 층을 포함하는 합충형파해를 원국 및 직전 상위 운과 비교한다. 관계가 건드리는 오행이 보완 후보에 맞는지에 따라 점수가 달라진다. 합/충을 일괄 길/흉으로 취급하지 않는다. 관계 계수와 상한은 자체 응용이다.
- 6개 조합에서는 기존 오행 분산·음양·중복 억제도 사용한다. 최종 `analysis_score`는 정규화된 방식 내부 적합도이며 당첨확률이나 다른 방식과의 우열이 아니다.

## 범위와 한계

프롬프트의 건강·연애·직업 진단, 페르소나/대화 지침, 고정 날짜 리포트는 로또 컴포넌트에 이식하지 않는다. 천덕/월덕 등 실제 조견표가 빠진 신살 규칙을 임의로 채우지 않는다. 이번 릴리스의 명리 입력은 기존처럼 **확정한 출생시간이 필수**다. 원문의 '시간 미상 3주 분석'까지 지원한다고 주장하지 않으며 이는 별도 입력·불확실성 설계가 필요한 미적용 항목이다.

원본 출생정보와 새 파생 명리 설명 모두 HA AI 프롬프트에서 제외한다. 구성 정보·파생 센서 속성은 사용자의 HA 안에 남는다. HA 백업/Recorder에는 포함될 수 있으므로 HA 접근권한과 백업 보호는 사용자가 관리해야 한다. GitHub 공유 로또 미러로 개인정보를 전송하지 않는다.
