# 검증 범위와 한계 · v1.6.0

## 구분

- **규칙 재현**: 제공 프롬프트의 표·원칙과 구현을 대조. 서로 다른 표나 오류는 `SAJU_RULES.md`에 공개.
- **소프트웨어 검증**: 범위·중복·과거 완전일치·재생성·설정 화면·개인정보 전달을 시험.
- **예측 효과**: 위 두 검증과 다릅니다. 과거 성적이 높아도 미래 로또 확률 상승을 입증하지 않습니다.

## 나머지 15개 방식에서 수정한 실제 문제

1. 같은 지표 값인데 번호가 클수록 더 높은 순위 점수를 주던 처리를 **동점 평균 순위**로 변경. 후보 최종 동점 결정은 재현성을 위한 정렬 규칙이며 무작위 균등 추출이라고 주장하지 않음.
2. 베이지안 사후평균을 순위 변환하면서 수축 크기가 소실되던 문제 수정. Beta(6,39) 사전분포와 60회 자료의 사후평균 편차를 고정 척도의 tanh로 정규화. 사전 강도가 커지면 실제 영향도도 중립으로 줄어드는지 시험.
3. 개별 번호/최종 구성요소 가중치 각각 합계 1로 정규화하고 최종 적합도 0~1 제한. **적합도는 확률이 아님**.
4. 후보 번호대와 균형 지표의 구간을 `1~10 / 11~20 / 21~30 / 31~40 / 41~45`로 통일.
5. 이월수 0개를 근거 없이 낮추던 고정값 대신 `C(6,k)C(39,6-k)/C(45,6)` 분포 비중 사용. 개수별 범주 크기이며 그 범주의 개별 티켓 확률을 높이는 것은 아님.
6. 표본이 없어 재등장 주기를 계산할 수 없는 번호는 임의의 7회 주기를 만들지 않고 중립 처리.
7. 모든 후보의 상세 사전을 메모리에 쌓지 않고 상위 1,200개만 힙으로 유지. 과거 당첨 완전일치·현재 게임 중복·직전 재생성 조합은 항상 제외하며, 다양성 조건 완화가 이 제외조건을 해제하지 못하도록 수정.
8. 수동 재생성의 직전 제외 목록을 저장하여 재시작 후에도 같은 세대의 선택 결과가 바뀌지 않도록 유지. AI 호출 없이 비AI 조합만 교체.
9. 명리를 선택하지 않은 통계 분석에 잘못된 사주 입력이 영향을 주지 않도록 분리. 명리만 선택했으나 프로필이 없는 경우 기본 5개 게임이 몰래 생성되지 않음.
10. 핫넘버 설명은 절댓값 변화 대신 부호 있는 변화 기준으로 일치. 균형/델타의 고정 수치 및 다중시간대의 실제 사용 구간을 설명에 명시.
11. AI 숫자의 소수·불리언·NaN·무한대가 정수로 변환되어 통과하지 못하도록 검증 강화. 명리 해석 문장도 AI 프롬프트에서 제외.

## 과거 실데이터 재생

`python scripts/audit_formulas.py --rounds 26 --workers 4`

릴리스에 원래 들어 있던 **1~1240회 스냅샷**을 사용합니다. 각 테스트 회차 t의 결과를 숨기고 **1~t-1 전체**만 엔진에 전달합니다. 데이터 수집이나 동행복권 요청, AI 호출은 하지 않습니다. 명리 프로필은 소스에 명시한 **인공 테스트 프로필**이며 사용자의 실제 사주가 아닙니다. 16개 방식은 실제 실행 순서와 후보규칙 그대로 함께 실행합니다.

결과 파일:
- `formula-audit-predictions.csv`: 회차별 실제 예측6개·당첨6개·일치 개수.
- `formula-audit-results.json`: 스냅샷 해시, 테스트회차, 방법별 평균·최대일치·검정결과.

검정 기준은 **Hypergeom(45,6,6)**의 정확한 회차별 일치 개수 분포를 회차 수만큼 합성한 단측 상위꼬리확률입니다. 방식16개 비교에는 Bonferroni 보정을 병기합니다. 회차별 여러 티켓은 서로 상관될 수 있으므로 이를 모두 독립 표본으로 합쳐 유의성을 부풀리지 않습니다.

**주의:** 과거 결과는 개발 당시에 이미 공개돼 있었습니다. 이는 사전등록한 독립 검증이 아닌 **탐색적 과거 재생**입니다. 작은 표본에서 가장 좋은 방식을 고르는 것은 성능 입증이 아닙니다. 결과를 보고 가중치를 재조정하지 않습니다. 다음 회차를 미리 고정한 전향적·장기 검증은 수행하지 않았습니다.

모든 고정된 6개 조합의 균등추첨 1등 확률은 `1 / C(45,6) = 1/8,145,060`, 기대 일치 개수는 `6×6/45 = 0.8`입니다. 참고 수학 정의: https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.hypergeom.html

## 배포 검증

`Validate`의 Python 테스트, 실제 HA OptionsFlow 시험, Hassfest가 모두 성공한 **동일 main 커밋**만 Release를 생성합니다. 체크 도중의 실패 커밋을 먼저 배포하지 않고 기존 태그를 덮어쓰지 않습니다. 로고/브랜드 바이너리, 공유 미러, 공식 접근 제한은 이번 변경에서 바꾸지 않습니다.
