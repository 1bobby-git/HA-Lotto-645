# 과거 회차 검증

## 용도와 실행

로또 복권 패널의 **과거 검증** 탭에서 회차를 선택하고 **검증번호 생성·당첨 확인**을 누릅니다. 기본 회차는 저장된 공식 이력의 최신 완료 회차이며, 검증 공식은 현재 통합의 선택 목록으로 시작합니다. 검증 화면에서 공식을 바꾸어도 실제 통합 설정·센서 선택은 바뀌지 않습니다.

검증은 버튼을 눌렀을 때만 실행합니다. 탭 이동·공식 안내 열기·주기적 상태 동기화는 검증을 다시 실행하지 않습니다. 최신 검증 결과 한 건과 현재 주기의 누적 점수를 HA 로컬 저장소에 보관합니다. 페이지 이동·브라우저 새로고침·HA 재시작 후에도 복원합니다. 한 번에 한 회차를 검증합니다.

## 데이터 경계: 1200회 예시

```text
생성에 사용: 1~1199회 당첨 데이터
                  ↓
현재 버전 추첨 공식으로 검증번호 6개 생성
                  ↓
생성이 끝난 뒤에만 1200회 당첨번호·보너스와 대조
                  ↓
검증번호, 본번호 일치 개수, 보너스 일치, 당첨 등수 표시
```

1200회 자체와 1201회 이후 데이터는 빈도·순위 변환·동반출현·전이·미출현·사주 추첨일·난수·합의·과거 1등 제외 목록을 만드는 데 전달하지 않습니다. 과거 1등 완전일치 제외도 **1199회까지**만 적용합니다. 따라서 1200회 당첨 조합이 1199회 이전에 나온 적이 없다면 검증 후보에서 미리 제외되지 않습니다.

각 공식이 원래 사용하는 기간은 유지됩니다. 가령 최근 10회는 **1190~1199회**, 최근 30회는 **1170~1199회**이며, 전체 이력 공식은 **1~1199회**를 사용합니다. 대상 회차의 결과는 생성이 끝난 뒤 평가 함수에만 전달합니다. 속보·출처 불일치·미래 결과가 아니라 저장된 공식 이력만 사용합니다.

기존 엔진에 최소 30회 데이터가 필요하므로 **31회부터** 검증합니다. 1회부터 직전 회차까지 빠짐없는 이력이 없거나 대상 공식 결과가 없으면 오류를 표시하며 임의 보완하지 않습니다.

## 실제 추천·리뷰와의 분리

| 항목 | 실제 추천·리뷰 | 과거 검증 |
|---|---|---|
| 번호 | 실제 생성 당시 저장된 번호 | 현재 버전 공식으로 지금 다시 만든 번호 |
| 생성시각 | 원래 저장된 실제 시각 유지 | 현재 검증 실행시각 |
| 당첨 대조 | 실제 저장번호의 해당 회차 결과 | 새 검증번호의 선택 회차 결과 |
| 별점·리뷰 점수 | 추첨 전에 기록한 실제 추천만 사용 | 확인 후 리뷰에 **과거검증 성과**로 추가. 실전 별점·당첨 횟수는 변경하지 않음 |
| 저장 | 기존 추천·리뷰·구매 저장소 | 통합별 `lotto_645.validation_scores.{entry_id}`에 분리 보관 |
| 센서와 합의 | 현재 실제 추천 데이터 | 별도 계산 결과, 센서에 게시 안 함 |

검증 경로는 실제 코디네이터의 새로고침·재생성·저장·스냅샷·리뷰 갱신 메서드를 호출하지 않습니다. 현재 추천 캐시, 재생성 제외 조합, 현재 난수 결과, 누적 별점도 입력으로 쓰지 않습니다. `counts_toward_reviews=false`, `persisted=false`, `mode=historical_validation`을 응답에 고정하고, 화면도 이를 확인합니다. 여기서 두 false 값은 기존 실전 추천·리뷰 원장에 저장하지 않는다는 뜻입니다. 별도 검증 저장 여부는 `validation_scoreboard_persisted`가 나타냅니다.

다른 통합으로 전환하거나 입력을 바꾼 뒤 늦게 도착한 응답은 폐기합니다. 검증 중에도 다른 탭의 실제 데이터 표시·동기화는 별도 동작합니다.

## 공식별 처리

**로컬 추첨 공식**은 실제 엔진의 같은 계산 규칙을 이전 회차 데이터에 적용합니다. 검증 화면의 공식 순서로 실행하며 실제 추천 캐시를 복원하지 않습니다.

**합의 추천**은 이 검증에서 생성한 다른 로컬 공식들의 번호만 집계합니다. 현재 센서값과 AI는 합의에 포함하지 않습니다. 로컬 원본 공식 2개 이상이 필요합니다. 중앙값 ±1 범위에 유효 후보가 없으면 `생성 불가`로 표시하고, 미당첨 게임으로 취급하지 않고 생성 불가 횟수를 따로 누적합니다. 리뷰에 반영할 때도 생성 불가 정보는 유지합니다.

**명리 공식**은 현재 저장된 사주 설정을 사용하되 과거 기준시점의 다음 추첨일로 계산합니다. 이는 당시 저장되어 있던 개인 설정의 복원이 아닙니다. 사주정보가 없으면 선택할 수 없습니다. 원본 사주정보는 검증 응답이나 외부 AI에 전송하지 않습니다.

**Home Assistant AI 추천**은 현재 번호 생성부인 CCSS만 재실행하여 `CCSS 번호만 검증`이라고 표시합니다. AI 설명 서비스는 호출하지 않습니다. 과거 결과를 본 AI에게 번호 예측을 맡기지 않고, AI 사용료도 발생시키지 않습니다.

## 매 실행 새 번호와 해석

버튼을 누를 때마다 운영체제 난수로 새 후보를 생성합니다. 사용자가 입력하거나 고정할 난수 설정은 없습니다. 점수형 공식도 상위 후보를 순환하며 직전 같은 회차의 검증 조합은 다시 선택하지 않습니다. 난수 공식·AI 번호 생성부·합의 결과에도 이전 검증 제외를 적용합니다. 불가능한 합의는 기준을 바꾸지 않고 생성 불가로 표시합니다.

번호 일부가 이전과 겹칠 수는 있지만 직전 검증의 여섯 번호 조합을 그대로 재사용하지 않습니다. 이 제외 목록은 통합별 직전 한 배치만 메모리에 보관하고, 다른 회차를 검증하거나 통합을 다시 불러오면 초기화됩니다. 실제 추천·구매·리뷰 저장소와 분리됩니다.

화면에 기준 회차, 사용 이력 수, 실행 버전, 생성시각과 입력 이력의 SHA-256을 제공합니다. 추가 설정 없이 회차와 공식만 선택하면 됩니다.

이 기능은 **현재 버전 공식을 과거에 재실행하는 시뮬레이션**입니다. 과거 코드 버전이나 당시 추천을 복원한 결과가 아니며, 나중에 설계한 공식·가중치의 선택 편향까지 없앤 독립적인 예측력 증명이 아닙니다. 여러 번 공식을 반복 실행해 좋은 결과만 고르는 것은 예측력의 근거가 될 수 없습니다.

## 통합 순위 목록과 점수

공식 하나당 행 하나에 **순위·공식명 / 이번 검증번호·일치 개수·당첨 등수 / 누적 점수·3개 이상 적중 비율**을 함께 표시합니다. 모바일은 같은 행 안에서 줄바꿈하며, 상세 통계는 펼쳤을 때만 표시합니다. 1·2·3위는 금색 계열·청회색·동색 계열 글자와 옅은 배경을 사용하고, 실제 당첨 등수 색상은 순위와 별도로 구분합니다. 동점은 공동 순위입니다.

본번호 일치 점수는 3개=1점, 4개=3점, 5개=10점, 6개=50점입니다. 보너스는 실제 당첨 등수에는 사용하지만 이 누적 점수에는 가산하지 않습니다. 정상 완료한 실행마다 총 검증 수를 1회 올리고, 0~2개 일치도 생성 횟수에 포함합니다. **누적 점수 / 이번 일치 개수 / 100회당 점수**로 정렬할 수 있습니다. 생성하지 않은 공식은 이번 결과를 지어내지 않고 누적 정보만 표시합니다.

## 새 당첨회차 확인 시 초기화

화면은 다음 정책을 항상 안내합니다.

> 새 당첨회차가 공식 이력 또는 교차확인 결과로 확인되면 검증 횟수·점수·결과를 초기화합니다. 이미 리뷰에 반영한 과거검증 성과와 실제 추천 리뷰는 유지됩니다.

시계가 추첨 예정시각을 지났다는 이유로 초기화하지 않습니다. 단일 출처의 잠정 결과·출처 충돌·동일 회차 재조회·낮은 회차 응답도 초기화하지 않습니다. HA가 중단된 동안 발표된 회차는 다음 시작 때 새 결과를 확인하면 처리합니다. 계산 도중 새 회차가 확인되면 오래된 계산이 끝나더라도 새 주기에 다시 더하지 않습니다.

업데이트 시 v1.16의 누적 점수는 처음 확인한 최신 회차를 기준점으로 삼아 보존하고, 그 다음 새 회차부터 초기화합니다. 과거에 저장하지 않았던 개별 검증 자료나 당시 버전은 새로 만들어 넣지 않습니다.

## 확인 후 실제 리뷰 화면에 반영

**리뷰에 반영** 버튼을 누르면 아직 반영하지 않은 검증 횟수와 출처를 확인합니다. 취소하면 아무 데이터도 바꾸지 않습니다. 승인하면 미적중·생성 불가를 포함한 전체 검증 집계의 미반영 증가분만 보관합니다. 같은 결과를 반복 승인해도 중복 누적되지 않습니다. 다른 화면에서 검증을 더 했거나 새 회차로 초기화됐다면 기존 확인은 거부하고 최신 상태를 다시 보여 줍니다.

리뷰 목록의 각 공식에 **반영한 과거검증 성과**를 표시하며, 기존 실전 순서 또는 반영된 과거검증의 **100회당 점수순**으로 비교할 수 있습니다. 과거검증으로 실제 추천 당시의 시각·별점·당첨 횟수를 덮어쓰지 않습니다. 반영 데이터는 다음 주기 초기화 후에도 유지됩니다.

## 비교의 품질과 추가 정보

- **100회당 점수**: 누적 점수 ÷ 실제 생성 횟수 ×100. 검증 실행 횟수 차이를 보정한 기술 통계이지 다음 회차 성공 확률이 아닙니다.
- **무작위 기준**: 공정한 6/45 추첨에서 고정된 한 게임의 본번호 3개 이상 일치 확률은 `sum(C(6,k)×C(39,6-k), k=3..6) / C(45,6)` = 약 **2.3834%**입니다. 관측 비율과 비교할 수 있으나 사후 재실행·후보 제외·공식 선택 편향을 제거한 우위 검정은 아닙니다.
- **서로 다른 회차의 첫 결과**: 같은 회차 재실행을 독립된 추첨 표본처럼 늘리지 않고 각 공식의 회차별 첫 생성 결과만 따로 집계합니다. 100개 미만 회차는 제품상 `표본 부족`으로 표시합니다. 100개 이상이어도 우위가 입증됐다는 뜻은 아닙니다.
- **99% 참고 구간**: 위 첫 결과의 3개 이상 적중 비율에 Wilson 구간을 계산합니다. 독립적인 베르누이 표본이라는 가정 아래의 기술 통계이며, 여러 공식을 고른 효과나 데이터에 맞춰 공식을 설계한 선택 편향은 보정하지 않습니다. 공식 버전이 섞이면 구간 비교를 생략합니다. 가장 높은 공식의 구간이 무작위 기준을 넘더라도 자동으로 ‘검증된 예측 공식’이라 판정하지 않습니다.
- **검증 회차 범위 차이 알림**: 공식마다 검증한 회차 집합이 다르면 직접 비교 주의를 표시합니다. 같은 기간·같은 공식 버전으로 비교하고 다음 실제 추첨의 리뷰로 재확인해야 합니다.
- **CSV 내보내기**: 현재 주기 공식별 집계를 출처·주기·버전과 함께 내보냅니다. 원본 개인 사주정보·토큰은 넣지 않고, 스프레드시트 수식으로 오인될 수 있는 문자열도 이스케이프합니다. 최근 상세 이력은 50건, 전체 개별 번호는 최신 결과 한 건만 보관하므로 CSV는 모든 과거 게임의 원본 로그가 아니라 누적 집계입니다.

이 릴리스에는 추가 외부 AI 호출, 자동 대량 백테스트, 결과를 본 뒤의 가중치 자동 조정, 당첨 보장을 추가하지 않았습니다. 실제로 제공하는 개선은 결과를 한눈에 보고, 불공정한 비교를 줄이며, 검증 자료를 출처와 함께 리뷰에 남기는 기능입니다.

## 구현 및 회귀 검사

- `historical_validation.py`: 연속 이력 절단 → 격리된 생성 → 대상 회차 평가. 파일·네트워크·리뷰 저장 접근 없음.
- `historical_validation_runtime.py`: HA executor에서 계산하며 통합별 단일 작업 제한. 호출 취소·180초 제한시간 초과 후에도 worker 종료 전에는 새 작업을 시작하지 않음.
- `historical_validation_scores.py`: 주기 초기화·원자적 저장·미반영 증가분 가져오기·통계·v1.16 자료 마이그레이션.
- `validation_lifecycle.py`: 코디네이터 결과 변경을 구독하여 새 회차 처리. 네트워크 폴링 추가 없음.
- `lotto_645/historical_validate`: 기존 관리자 전용 패널의 인증된 WebSocket 명령. 공식·회차 엄격 검증 및 종료된 공식 거부.
