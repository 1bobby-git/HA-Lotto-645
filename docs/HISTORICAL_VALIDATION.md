# 과거 회차 검증

## 용도와 실행

로또 복권 패널의 **과거 검증** 탭에서 회차를 선택하고 **검증번호 생성·당첨 확인**을 누릅니다. 기본 회차는 저장된 공식 이력의 최신 완료 회차이며, 검증 공식은 현재 통합의 선택 목록으로 시작합니다. 검증 화면에서 공식을 바꾸어도 실제 통합 설정·센서 선택은 바뀌지 않습니다.

검증은 버튼을 눌렀을 때만 실행합니다. 탭 이동·공식 안내 열기·주기적 상태 동기화는 검증을 다시 실행하지 않습니다. 결과는 현재 화면의 메모리에만 보관하며 브라우저를 새로고침하면 사라집니다. 한 번에 한 회차를 검증합니다.

## 데이터 경계: 1200회 예시

```text
생성에 사용: 1~1199회 당첨 데이터
                  ↓
현재 버전 추첨 공식으로 검증번호 6개 생성
                  ↓
생성이 끝난 뒤에만 1200회 당첨번호·보너스와 대조
                  ↓
검증번호, 본번호 일치 개수, 보너스 일치, 당첨 등수 표시
```

1200회 자체와 1201회 이후 데이터는 빈도·순위 변환·동반출현·전이·미출현·사주 추첨일·난수·합의·과거 1등 제외 목록을 만드는 데 전달하지 않습니다. 과거 1등 완전일치 제외도 **1199회까지**만 적용합니다. 따라서 1200회 당첨 조합이 1199회 이전에 나온 적이 없다면 검증 후보에서 미리 제외되지 않습니다.

각 공식이 원래 사용하는 기간은 유지됩니다. 가령 최근 10회는 **1190~1199회**, 최근 30회는 **1170~1199회**이며, 전체 이력 공식은 **1~1199회**를 사용합니다. 대상 회차의 결과는 생성이 끝난 뒤 평가 함수에만 전달합니다. 속보·출처 불일치·미래 결과가 아니라 저장된 공식 이력만 사용합니다.

기존 엔진에 최소 30회 데이터가 필요하므로 **31회부터** 검증합니다. 1회부터 직전 회차까지 빠짐없는 이력이 없거나 대상 공식 결과가 없으면 오류를 표시하며 임의 보완하지 않습니다.

## 실제 추천·리뷰와의 분리

| 항목 | 실제 추천·리뷰 | 과거 검증 |
|---|---|---|
| 번호 | 실제 생성 당시 저장된 번호 | 현재 버전 공식으로 지금 다시 만든 번호 |
| 생성시각 | 원래 저장된 실제 시각 유지 | 현재 검증 실행시각 |
| 당첨 대조 | 실제 저장번호의 해당 회차 결과 | 새 검증번호의 선택 회차 결과 |
| 별점·리뷰 점수 | 원래 회차에 저장된 실제 추천만 사용 | **반영 안 함** |
| 저장 | 기존 추천·리뷰·구매 저장소 | **저장 안 함** |
| 센서와 합의 | 현재 실제 추천 데이터 | 별도 계산 결과, 센서에 게시 안 함 |

검증 경로는 실제 코디네이터의 새로고침·재생성·저장·스냅샷·리뷰 갱신 메서드를 호출하지 않습니다. 현재 추천 캐시, 재생성 제외 조합, 현재 난수 결과, 누적 별점도 입력으로 쓰지 않습니다. `counts_toward_reviews=false`, `persisted=false`, `mode=historical_validation`을 응답에 고정하고, 화면도 이를 확인합니다.

다른 통합으로 전환하거나 입력을 바꾼 뒤 늦게 도착한 응답은 폐기합니다. 검증 중에도 다른 탭의 실제 데이터 표시·동기화는 별도 동작합니다.

## 공식별 처리

**로컬 추첨 공식**은 실제 엔진의 같은 계산 규칙을 이전 회차 데이터에 적용합니다. 검증 화면의 공식 순서로 실행하며 실제 추천 캐시를 복원하지 않습니다.

**합의 추천**은 이 검증에서 생성한 다른 로컬 공식들의 번호만 집계합니다. 현재 센서값과 AI는 합의에 포함하지 않습니다. 로컬 원본 공식 2개 이상이 필요합니다. 중앙값 ±1 범위에 유효 후보가 없으면 `생성 불가`로 표시하고, 미당첨 게임이나 리뷰로 집계하지 않습니다.

**명리 공식**은 현재 저장된 사주 설정을 사용하되 과거 기준시점의 다음 추첨일로 계산합니다. 이는 당시 저장되어 있던 개인 설정의 복원이 아닙니다. 사주정보가 없으면 선택할 수 없습니다. 원본 사주정보는 검증 응답이나 외부 AI에 전송하지 않습니다.

**Home Assistant AI 추천**은 현재 번호 생성부인 CCSS만 재실행하여 `CCSS 번호만 검증`이라고 표시합니다. AI 설명 서비스는 호출하지 않습니다. 과거 결과를 본 AI에게 번호 예측을 맡기지 않고, AI 사용료도 발생시키지 않습니다.

## 재현 정보와 해석

시드 기본값은 **0**, 범위는 **0~4,294,967,295**입니다. 같은 버전·이력·공식 순서·사주 설정·시드에서는 같은 검증번호를 생성합니다. 난수 공식에는 검증 전용 시드 난수를, 점수 기반 공식에는 같은 시드 값의 후보 순환 순번을 사용합니다. 실제 운영 난수는 바꾸지 않습니다. `rng=seeded_simulation_prng`이며 운영체제 CSPRNG 추첨이었다고 표시하지 않습니다.

화면에 기준 회차, 사용 이력 수, 실행 버전, 시드, 생성시각과 입력 이력의 SHA-256을 제공합니다. 미래 회차가 추가되어도 이전 검증의 입력 해시는 같지만, 입력 기간의 공식 이력이 정정되면 해시와 결과가 바뀔 수 있습니다.

이 기능은 **현재 버전 공식을 과거에 재실행하는 시뮬레이션**입니다. 과거 코드 버전이나 당시 추천을 복원한 결과가 아니며, 나중에 설계한 공식·가중치의 선택 편향까지 없앤 독립적인 예측력 증명이 아닙니다. 여러 시드·공식을 반복 실행해 좋은 결과만 고르는 것은 예측력의 근거가 될 수 없습니다.

## 구현 및 회귀 검사

- `historical_validation.py`: 연속 이력 절단 → 격리된 생성 → 대상 회차 평가. 파일·네트워크·리뷰 저장 접근 없음.
- `historical_validation_runtime.py`: HA executor에서 계산하며 통합별 단일 작업 제한. 호출 취소·180초 제한시간 초과 후에도 worker 종료 전에는 새 작업을 시작하지 않음.
- `lotto_645/historical_validate`: 기존 관리자 전용 패널의 인증된 WebSocket 명령. 공식·회차·시드 엄격 검증.
- `tests/test_historical_validation.py`: 대상/미래 번호 변경 불변성, 목표 1등 조합 사전 제외 금지, 재현, 최소 이력, 잘못된 입력, 취소·제한시간·단일 실행, 실제 상태 무변경.
- `scripts/smoke_historical_validation.py`: 실제 HA 데코레이터·관리자 권한·스키마 및 추천/리뷰/구매 메모리·저장 파일 바이트 무변경 검사.
- `scripts/smoke_panel_validation.py`: 실제 브라우저 탭·명시적 실행·일치 표시·모바일·고대비·입력 변경·다른 통합의 늦은 응답 폐기.
