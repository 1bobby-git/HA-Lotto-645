# 추첨번호·추천 요약·직접 구매번호 · v1.9.0

## 센서별 역할

| 센서 | 화면에 표시되는 값 | 상세 속성 |
|---|---|---|
| **n회 추첨번호** | 최신으로 받아들인 회차의 본번호 6개 | 회차·추첨일·보너스번호·데이터 출처 |
| **당첨 여부** | 같은 회차의 저장번호 중 당첨 게임 수와 최고 등수, 또는 전체 미당첨 | 추첨 공식/AI/직접 구매 A–E별 결과, 실제 연결 엔티티 ID, 일치 본번호, 보너스 여부, 분리 집계 |
| **내 구매번호** | 마지막으로 저장·수정한 회차의 등록 게임 수·대기/당첨 결과 | A–E의 입력번호·게임별 등수·일치번호, 저장된 회차 목록 |
| **추천 요약** | 추천 **대상 회차** | `games`에 선택한 공식별 추천 6개·핵심 근거, 생성시각·방법·기준 회차 등 |
| **추첨 공식 안내** | 지원하는 추첨 공식 수 | 방법별 설명 |

`추천 요약` 값이 `1242`라면 **1242회에 사용할 추천 결과**라는 뜻입니다. 점수, 당첨 개수, 이미 발표된 추첨번호가 아닙니다. 요약은 또 하나의 추천 게임을 만들거나 당첨 판정에서 중복 집계하지 않습니다. 구매번호도 추천 계산/AI 입력에 섞지 않습니다.

추첨번호 이름은 실제 수신 회차를 따라 `1241회 추첨번호`처럼 바뀝니다. 기존 `draw_numbers` unique_id와 등록된 entity_id는 바꾸지 않으므로 자동화에서 회차마다 새 엔티티를 지정할 필요가 없습니다. HA에서 사용자가 직접 지정한 별도 이름이나 카드 제목은 자동 덮어쓰지 않습니다.

## 구매번호 입력: 회차별 최대 5게임

```text
설정 → 기기 및 서비스 → Lotto 6/45 Analysis → 구성
→ 직접 구매번호 입력·수정
→ 복권에 인쇄된 회차 입력
→ A / B / C / D / E 게임 입력 → 확인
```

각 게임은 **1~45에서 서로 다른 번호 6개**입니다. 1~5게임을 저장할 수 있고 나머지 칸은 비워둡니다. 입력 예시는 형식 설명이며 실제 구매한 번호가 아닙니다.

- `1, 5, 9, 14, 28, 45` 또는 `1 5 9 14 28 45`처럼 쉼표/공백으로 구분합니다. 슬래시·세미콜론도 지원합니다.
- 모든 번호를 두 자리로 쓴 `010509142845`도 같은 조합으로 인식합니다.
- `159142845`처럼 자리 구분이 모호한 입력이나 단순 6자리 문자열은 임의로 분할하지 않고 오류를 표시합니다.
- 한 게임 내부의 중복·0·46 이상·소수·6개가 아닌 입력은 해당 A–E 칸에 오류로 표시하고 **전체 저장을 취소**합니다.
- A와 B에 같은 조합을 실제 두 장 구입했다면 두 게임을 모두 저장·집계합니다. 알고리즘 추천의 과거 당첨번호 제외 규칙은 구매번호에 적용하지 않습니다.

확인을 누르면 번호가 오름차순 표준 형식으로 저장됩니다. 같은 회차를 다시 열면 기존 A–E가 채워집니다. **저장은 선택한 회차의 A–E 전체를 교체**하므로 비운 칸은 그 회차에서 제거되지만 다른 회차는 그대로 남습니다. `이 회차의 구매번호 삭제`를 명시적으로 켰을 때만 해당 회차 전체를 삭제합니다.

새 주가 되어도 지난주의 구매번호를 다음 회차 구매로 복제하지 않습니다. 매주 실제 복권의 회차와 번호를 별도로 저장하세요. 과거 회차도 입력할 수 있으며 그 회차 결과가 이미 HA 캐시에 있으면 저장 직후 비교 결과를 볼 수 있습니다. 이는 실제 구매를 확인하거나 사전 예측 실적으로 인증하는 기능이 아닙니다.

## 결과 갱신 — v1.8.1의 수동 공식 유지

이번 변경은 앞서 적용한 **수동 새로고침 정책을 유지**합니다. 발표 예정 시각 자체로 결과를 만들어내지 않으며, 발표 즉시 수신을 보장하지 않습니다.

```text
즉시 새로고침 · 번호 재생성
→ 공유 미러의 새 회차 수신
→ 새 회차로 바꾸기 전 보존한 추천 스냅샷과 결과 비교
→ 동일 회차의 구매 A–E도 결과 비교
→ 비AI 추천은 새 후보로 갱신
```

일반 주기 확인에서는 새 원격 회차를 받아들이지 않습니다. 새 추첨 결과는 수동 새로고침을 눌러 실제로 수신했을 때 센서에 반영됩니다. **구매번호를 저장·수정·삭제하는 동작은 네트워크 요청, AI 생성, 추천 번호 재생성을 실행하지 않습니다.** 수동 새로고침도 구매번호 자체를 바꾸지 않습니다.

`당첨 여부`는 최신 수신 추첨 회차 기준으로 추천·구매 결과를 함께 보여줍니다. `내 구매번호`는 마지막 저장 회차 기준입니다. 따라서 1241회가 발표된 뒤 1242회 복권을 입력했다면 `당첨 여부`는 1241회 판정, `내 구매번호`는 1242회 대기가 됩니다. **결과가 없는 회차나 등록하지 않은 게임을 미당첨으로 계산하지 않습니다.**

순위: 본번호6개=1등, 본번호5개+보너스=2등, 본번호5개=3등, 본번호4개=4등, 본번호3개=5등, 나머지 미당첨. 보너스만 맞거나 본번호2개+보너스는 당첨으로 계산하지 않습니다.

`당첨 여부`의 `results`, `winners`, `losers`에는 해당 추천 센서 연결 정보 또는 `내 구매번호`와 A–E 구분이 들어갑니다. `recommendation_game_count`와 `purchased_game_count`, 각각의 당첨 수를 나누어 표시하므로 **추천만 맞은 경우를 실제 구입 당첨으로 혼동하지 않습니다.**

## 저장·개인정보·오류 처리

구매번호는 추천 설정과 분리된 HA 로컬 `.storage/lotto_645.purchases.<entry_id>`에 회차별 저장됩니다. 재시작 후 복원하며 명시적으로 삭제하지 않은 다른 회차를 자동 정리하지 않습니다. 저장 실패 시 메모리의 기존 번호도 교체하지 않습니다. 읽을 수 없는 구매 저장소가 발견되면 원본을 보존하고 쓰기를 막으며 추천 기능은 별도로 유지합니다.

구매번호를 GitHub, 공유 미러 또는 외부 AI 공급자에 전송하지 않습니다. 사용자의 HA 상태/Recorder·백업에는 들어갈 수 있으므로 관리자 접근 및 백업 권한을 보호하세요. 공개 저장소의 테스트 데이터는 모두 합성 예시입니다.

이 컴포넌트는 **구매번호 대조 도구**이며 실제 복권 구매·소유권·당첨금 수령·지급액을 확인하지 않습니다. 최종 확인은 복권 원본과 공식 결과를 기준으로 하세요.
