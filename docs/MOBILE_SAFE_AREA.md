# 모바일 헤더 안전 영역 — v1.11.3

## 원인

패널 등록의 `handle_safe_area: true`는 Home Assistant의 기본 안전 여백을 끄고 패널이 직접 처리한다는 의미입니다. 이전 헤더는 해당 여백을 소비하지 않아 iOS 전체 화면에서 메뉴·로고·설정이 상태바와 다이내믹 아일랜드에 겹칠 수 있었습니다.

참고: [Home Assistant의 안전 영역 계약](https://developers.home-assistant.io/blog/2026/07/31/frontend-component-updates-2026.8/#safe-area-handling), [WebKit의 안전 영역 설명](https://webkit.org/blog/7929/designing-websites-for-iphone-x/).

## 수정

- 헤더 위에 `--safe-area-inset-top`을 반영합니다. HA 변수가 없을 때만 `env(safe-area-inset-top, 0px)`을 사용합니다. 특정 기종의 59px 같은 값을 운영 코드에 고정하지 않습니다.
- HA가 제공한 0도 유효한 값으로 존중합니다. HA 값과 브라우저 값을 더하지 않으므로 같은 안전 영역을 두 번 적용하지 않습니다.
- 본문·탭·헤더의 좌우는 기존 반응형 여백과 안전 여백 중 큰 값을 사용합니다. 사이드바가 이미 소비한 쪽은 `--safe-area-content-inset-left/right`를 우선합니다.
- 최상위 레이어에 열리는 등록·수정 dialog는 본문 여백의 영향을 받지 않으므로 별도로 상단·좌우 안전 영역을 적용합니다. 저장 버튼과 알림은 하단 홈 인디케이터를 피합니다.
- 화면 회전 시 CSS 변수를 다시 계산하며 별도의 기종 판별·타이머·네트워크 요청은 추가하지 않습니다.
- 안전 영역이 없는 데스크톱에서는 기존 여백·헤더 높이를 유지합니다. 원본 로고, 흰색 결과 카드, 번호 색상, 탭 구조, QR·저장·추천·AI 로직과 엔티티 ID는 그대로입니다.

## 검증

`scripts/smoke_ticket_panel.py`의 기존 실제 모듈·원본 로고·PNG QR·저장 검사를 유지하고 `smoke_panel_safe_area.verify_safe_area`를 추가했습니다. 320~1440px, 세로·가로, 라이트·다크, 상단 0/24/47/59/62px, 좌우 59px와 사이드바 흡수 조건 등 24개 모의 조합을 검사합니다.

헤더 요소의 위치·겹침, 여러 통합 선택 행, dialog 닫기·저장 버튼 위치, 알림의 하단 여백, 본문 넘침, Escape와 초점 복귀를 실제 렌더링 좌표로 확인합니다. 시험용 inset은 실기기 측정값을 주장하는 것이 아닙니다. 변경 전 소스에서 상단 47px 조건이 실패하는 것도 재현했습니다.

로컬에서 24개 조합과 기존 미리보기 UI 회귀 77개를 통과했습니다. 로컬 미리보기에는 기존 시안의 로고가 포함되며 최신 원본 로고와 실제 PNG QR 디코딩은 저장소 CI에서 별도로 확인합니다. 최종 CI 상태는 해당 커밋의 Actions 결과를 확인하세요. 실제 iOS 앱·Safari·물리 카메라·가상 키보드를 사용한 검증은 포함하지 않습니다.

## 업데이트

정식 릴리스가 게시되면 HACS에서 v1.11.3으로 업데이트하고 Home Assistant를 재시작하세요. 모바일 앱을 완전히 종료한 뒤 다시 열어 로또 복권 화면을 확인하세요. 통합 재등록이나 데이터 삭제는 필요하지 않습니다. 이 변경은 GitHub 배포이며 사용자의 HA 설치·재시작을 직접 실행하지 않습니다.
