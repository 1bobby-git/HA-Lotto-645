# v1.10.0 — 빠른 공개 결과와 QR 구매번호 입력

## 실제 사용 위치

설정 메뉴에 들어갈 필요 없이 **왼쪽 메뉴 → 로또 복권**을 엽니다. HA 관리자 로그인 세션을 사용하는 전용 화면입니다. 기존 구성 메뉴의 A~E 입력은 호환성을 위해 유지합니다.

- 카메라로 복권 QR 스캔 (HTTPS·브라우저 카메라 권한 필요)
- QR이 보이는 PNG/JPEG/WebP 사진 선택 (10MB 이하)
- 기본 카메라가 읽은 동행복권/기존645lotto QR 주소 붙여넣기
- 회차와 A~E 번호 직접 입력

QR을 읽으면 회차와 최대5게임이 입력란에 나타납니다. **아직 저장한 것이 아닙니다.** 실제 복권과 비교하고 **확인한 번호 저장**을 눌러야 HA 로컬 저장소에 기록됩니다. 같은 회차의5게임은 확인 후 교체되며 다른 회차는 보존됩니다. 다른 화면이 먼저 저장하면 변경 충돌을 알리고 덮어쓰지 않습니다. 삭제도 확인한 해당 회차만 삭제합니다.

QR 사진과 카메라 영상은 브라우저에서만 처리하며 외부 서버·AI에 전송하지 않습니다. `jsQR1.4.0`을 로컬 패키지에 포함하고 라이선스와 해시를 보존합니다. 번호 확인 과정에서 QR 주소를 방문하지 않습니다. 영수증 끝부분 식별값은 파싱 후 버리고 저장하지 않습니다. 결과는 실제 복권 구매·소유권·지급을 인증하지 않습니다.

현재 지원 QR은 `qr.dhlottery.co.kr/?v=...`, `m.dhlottery.co.kr/qr.do?method=winQr&v=...` 및 `qr.645lotto.net/?v=...` 계열의 회차+q/m/s+두자리번호6개 반복 형식입니다. n000000000000은 구매하지 않은 빈 슬롯으로 건너뛰며 A~E 위치를 보존합니다. 식별부10/18자리는 저장하지 않습니다. 변형되거나 지원하지 않는 형식은 임의 해석하지 않고 직접 입력을 안내합니다. 실제 사용자의 종이 복권 QR을 이 작업에서 시험한 것은 아닙니다. 합성 QR 사진을 이용한 로컬 브라우저 판독·미리보기·명시적 저장은 시험했습니다.

## 자동 갱신

GitHub Actions 예약 실행 시각이나 동행복권 공식 이력 갱신만 기다리지 않고, **HA 자체 시계**로 공개 결과를 확인합니다. 사용자의 HA 시간대와 관계없이 한국 시각 기준입니다.

| 한국 시각 | 확인 간격 |
|---|---:|
| 토요일20:35~21:30 | 약60초 |
| 토요일21:30~23:30 | 약5분 |
| 일요일00:00~10:00 | 약15분 |

방송 종료를 감지하는 실시간 영상 인식이 아닙니다. 예정 방송 시작 무렵부터 확인하여 **해당 회차 본번호6개와 보너스1개가 실제 공개되면 즉시 두 센서에 반영**하는 구조입니다. 매체의 게시시각, RSS 포함 여부, 접근 제한, 네트워크, HA 가동 여부는 제어할 수 없으므로 **방송 종료 후10분 이내를 보장하지 않습니다**. 예약 자체가 지연될 수 있는 중앙 GitHub cron을 빠른 수신의 필수 조건으로 사용하지 않습니다.

공개 경로는 SBS 경제 RSS, 연합뉴스 경제 RSS, 뉴시스 속보 RSS입니다. 검색 포털 네이버/다음의 자동 접근 제한을 우회하지 않습니다. 직접 확인된 공개 RSS 경로를 사용하되 매번 robots 정책을 캐시/확인하고, 403/429나 Retry-After를 받으면 해당 출처를 중단합니다. 본문이 짧은 RSS는 해당 기사의 허용된 HTTPS 주소만 제한적으로 읽습니다. QR 주소나 임의 URL을 HTTP 클라이언트에 전달하지 않습니다.

실제 네트워크 확인에서 SBS/연합뉴스/뉴시스 RSS HTTP200을 확인했습니다. 뉴시스 피드에는 **1241회, 7·13·16·23·24·43, 보너스9**가 있었고 원문 게시시각은 **2026-09-12 20:52:05(KST)**였습니다. 다운로드한 피드를 새 파서로 읽어 두 관련 기사의 번호가 일치하는 것을 확인했습니다. 이는 게시 후 받은 자료를 파싱한 검증이지, 방송 종료 시점부터10분 내 수신했다는 종단간 지연 측정은 아닙니다. SBS/연합뉴스의 최초 확인 피드에는 해당 회차 결과가 없었습니다. 이미 발표된1240회 형식 및 합성·오류·이전회차 테스트도 적용했습니다.

## 속보와 공식 확인 구분

- 한 언론사에서 회차·게시시각·본번호6개·보너스가 모두 유효하면 **속보 기준 · 공식 미대조**로 표시합니다.
- 다른 언론사 결과까지 일치하면 **복수 언론 일치 · 공식 미대조**입니다. 통신사 전재는 독립된 취재를 의미하지 않습니다.
- 번호/보너스/회차가 충돌하면 **출처 불일치 · 판정 대기**이며 그 값으로 당첨/미당첨을 단정하지 않습니다.
- 공식 이력 미러가 따라오면 같은 회차의 원래 추천·구매번호를 다시 대조하고 **공식 확인/정정**으로 바꿉니다.

속보는 공식 역사 데이터와 **분리된 결과 표시용 기록**입니다. 기존 추천 통계·명리·중앙값 합의가 미확인 번호를 학습하지 않습니다. 공식 이력이 늦으면 다음 회차 추천 자체는 이전 공식 이력 기준으로 남을 수 있으나, `n회 추첨번호`와 `n회 당첨 여부`, 구매번호 판정은 속보로 먼저 표시합니다. 공식 확인 이전의 당첨금/1등인원은 임의로 만들지 않습니다.

## 추첨 전 추천의 보존

추첨 예정 시작 이후 번호를 재생성해도 직전에 저장한 해당 회차 추천 스냅샷은 교체하지 않습니다. 처음 결과가 들어오면 그 스냅샷을 판정용으로 별도 고정하여 저장합니다. 속보가 바뀌거나 공식 정정이 와도 같은 번호로 재판정합니다. 생성시각이 추첨 예정 시작 이후이거나 미상인 추천은 **예측 결과 집계에서 제외**하며 미당첨으로 세지 않습니다. 속보가 아니라 공식 이력이 먼저 도착해도 동일한 기준을 적용하며 기존 판정 캐시도 새 기준으로 한 번 재검증합니다. 사용자 구매번호는 본인이 입력한 번호의 결과 대조이므로 추첨 후 등록도 허용하며 구매 인증으로 취급하지 않습니다.

일반 번호 재생성 버튼은 기존처럼 AI를 제외한 추천을 바꿉니다. 새 화면의 **추첨 결과 지금 확인**은 번호 재생성이나 AI 호출 없이 결과만 확인합니다. 기존17개 방식·AI·사주 입력·구매 저장 구조·엔티티 식별자는 유지됩니다.

## 검증 범위

- 순수 파서: 다른 회차, 미래 게시시각,7개 본번호,중복/범위오류,보너스 누락/충돌,외부URL/내부IP 및 XML 엔티티 거절.
- 속보 표시: 공식 이력을 변경하지 않음, 재시작 복원, 동일 스냅샷 유지, 공식 정정 재대조, 미상/늦은 추천 제외.
- QR: 현재/기존URL,자동/수동/반자동 1~5게임,자리수/범위/중복,알수없는호스트,중복쿼리,식별값 제거.
- 실제 HA2026.9.0 클래스: 기존 OptionsFlow/Store/센서 시험에 관리자 웹소켓·미리보기 무저장·명시적 저장·충돌 방지를 추가.
- Chromium: 로컬 jsQR로 합성 QR 사진을 판독하고 저장 전에는 구매 API가 호출되지 않음을 시험.
- 사용자의 실제 운영 HA/휴대폰 카메라/종이복권 및 실제 생방송 종료시각부터의 지연시간은 종단간 측정하지 않았습니다.
