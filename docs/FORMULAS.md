## 1. 입력 데이터와 추천 대상

각 로컬 방식은 분석 엔진에 전달된 공식 추첨 이력의 **본번호 6개**를 사용합니다. 보너스번호는 추천 점수 계산에서 제외하고 당첨 등위 판정에만 별도로 사용합니다. 추천 대상 회차는 마지막 분석 이력 회차의 다음 회차입니다. 속보 표시와 공식 분석 이력은 분리되어 있으므로 두 화면의 기준 회차가 일시적으로 다를 수 있습니다.

기간 단위는 일수가 아닌 **추첨 회차 수**입니다. 예를 들어 최근 30회는 최근 30일이 아닙니다. 창 길이보다 전달된 이력이 짧으면 실제 존재하는 회차 수를 사용합니다. 명리 방식은 추가로 사용자가 직접 저장한 개인 사주 프로필이 필요합니다.

## 2. 번호별 특징을 계산하는 방법

`p = 6/45`, `N = 관찰 회차 수`, `c = 해당 번호의 출현 횟수`라 하면 표준화 잔차는 다음과 같습니다.

```text
z = (c - N × p) / sqrt(N × p × (1-p))
```

양수는 관찰 구간의 출현이 무작위 기대 횟수보다 많았다는 뜻이고, 음수는 적었다는 뜻입니다. 다음 회차의 방향이나 확률을 직접 말하지 않습니다.

대부분의 원시 특징은 1~45 안에서 작은 값부터 큰 값으로 정렬한 **0부터 시작하는 평균 순위 / 44**로 0~1에 매핑합니다. 동점은 같은 평균 순위를 받아 번호가 크다는 이유로 유리해지지 않습니다. 모든 값이 같으면 모두 0.5가 됩니다. 이 상대순위를 아래 문서에서는 `R(특징)`으로 표기합니다.

예외도 있습니다. 베이지안 수축은 효과 크기가 지워지지 않도록 `0.5 + 0.5 × tanh(편차 / p)`를 사용합니다. 명리 적합도는 계산된 값을 그대로 사용합니다. 중앙값 방식은 다른 방식의 번호 점수를 집계합니다. 따라서 ‘모든 값을 순위로 바꾼다’는 설명은 정확하지 않습니다.

### 자주 쓰는 특징 사전

| 내부 키 | 실제 의미 |
|---|---|
| `frequency_10`, `frequency_30`, `frequency_100`, `frequency_long` | 해당 기간 출현 잔차의 상대순위 |
| `phase_velocity` | 최근 30회 잔차와 120회 잔차 차이의 **절댓값** 순위 |
| `phase_velocity_positive` | 같은 차이의 **부호 있는 값** 순위. 음수를 0으로 자르는 계산이 아님 |
| `curvature` | `abs((z30-z120)-(z120-z260))`의 순위 |
| `counter_phase` | `max(0, -z전체 × (z30-z120))`의 순위 |
| `transition` | 직전 번호 각각의 과거 출현 다음 회차에서 관찰한 후보 번호 잔차를 평균한 값의 순위 |
| `graph_strength`, `triplet_strength` | 번호별 강한 번호쌍·삼중 연결의 요약 순위 |
| `long_neutral`, `recent_neutral` | 각각 `-abs(z전체)`, `-abs(z30)`의 순위 |
| `gap_balance` | 미출현 간격의 기대값에서 멀지 않은 정도 |
| `gap_surprise` | 긴 쪽과 짧은 쪽을 모두 포함한 간격 이례성. 상한 2.5 |
| `overdue_capped` | 표준화 간격을 -0.5~2.4로 제한한 뒤 순위화 |
| `cycle_fit` | 현재 간격+1이 과거 재등장 간격 중앙값에 가까운 정도 |

현재 미출현 간격 `g`는 최신 회차에 등장했으면 0, 직전 회차에만 등장했으면 1입니다. 기대 미출현 간격은 `(1-p)/p = 6.5`, 표준편차는 `sqrt((1-p)/p²) ≈ 6.9821`입니다. 따라서 `gap_z = (g-6.5)/6.9821`, `gap_surprise = min(abs(gap_z),2.5)`, `gap_balance = -abs(gap_z)`를 원시 특징으로 사용합니다.

## 3. 번호 점수와 조합 점수는 다릅니다

각 문서의 **번호 단계 가중치**는 `methods.py`의 원시 설정값입니다.

```text
번호 점수(n) = Σ(특징 가중치 × 특징 점수(n)) / Σ(특징 가중치)
```

합계가 1이 아닌 경우에도 정규화합니다. 예를 들어 종합 앙상블의 번호 가중치 합은 0.90이므로 표의 0.10은 실제로 약 11.11%의 비중입니다.

6개 번호의 평균 점수만으로 끝나지 않습니다. 방식별로 조합 내부의 번호쌍, 삼중 연결, 변화 방향·간격 다양성, 균형, 델타, 이월, 명리 조합 점수를 함께 사용합니다.

```text
조합 기본점수 = Σ(조합 가중치 × 조합 요소 점수) / Σ(조합 가중치)
최종 score = 0~1 범위로 제한(조합 기본점수 - 과거 유사성 감점)
```

모든 방식에서 `individual`의 원시 가중치는 0.66입니다. 이것이 항상 최종 점수의 66%라는 뜻은 아닙니다. 예를 들어 위상잔차 그래프는 `0.66+0.20+0.10=0.96`으로 나누고, 중앙값은 다른 조합 요소 가중치가 0이므로 `individual` 비중이 100%입니다.

번호쌍 조합점수는 내부 15개 연결의 평균을, 삼중 조합점수는 내부 20개 연결의 평균을 각각 `(평균+1)/2`로 바꿉니다. `diversity`는 서로 다른 추천게임 간 중복률이 아니라 **한 조합 내부**의 변화 방향 혼합과 인접 간격의 표준편차를 결합한 값입니다. 추천게임 간 중복 제한은 다음 단계의 별도 규칙입니다.

### 공통 유사성 감점

직전 본번호와 겹친 수를 `k`, 후보 안의 4번호·5번호 부분집합 중 과거 반복 횟수 최댓값을 `q4`, `q5`라 하면:

```text
감점 = a × k + 0.012 × min(q4,3) + 0.026 × min(q5,2)
a = 이월 조합 가중치가 있는 방식은 0.007, 나머지는 0.023
```

이 감점과 과거 1등 완전일치 제외는 조합 성격을 정하는 장치입니다. 과거 조합이 다시 나올 수 없다는 뜻이 아니며 개별 조합의 확률을 올리지 않습니다.

## 4. 후보 풀에서 최종 1게임까지

방식별 번호 점수 상위 후보와 `1~10 / 11~20 / 21~30 / 31~40 / 41~45` 구간별 상위 후보를 함께 모아 22~26개 규모의 후보 풀을 구성합니다. 먼저 상위 `max(14, 풀 크기-10)`개, 다음으로 구간별 상위 2개 중 아직 없는 번호를 더하고, 부족하면 전체 순위에서 채웁니다. **최종 6개가 모든 구간을 반드시 포함한다는 조건은 아닙니다.**

풀에서 가능한 6개 조합을 평가해 상위 1,200개까지 유지합니다. 과거 1등 본번호와 완전히 같거나 이미 선택한 다른 방식의 조합 및 호출부가 전달한 제외 조합은 통과시키지 않습니다. 조합 점수가 같을 때는 작은 번호 튜플을 우선하는 결정적 동점 규칙이 있습니다.

이미 생성된 다른 방식과 겹침·번호 사용 횟수를 제한한 후보를 우선합니다. 후보가 없으면 부분 중복 허용치를 3→4→5개 순서로 완화하고 사용 횟수 제한도 완화하지만, 완전 동일 조합과 과거 1등 완전일치 제외는 완화하지 않습니다. 따라서 ‘항상 다른 방식과 3개 이하만 겹친다’는 보장은 없습니다. 선택 방식과 그 순서가 바뀌면 최종 번호도 바뀔 수 있습니다.

조건을 통과한 후보는 최대 64개를 남기며 초기 계산은 첫 후보를 사용합니다. 수동 재생성은 이 중 최대 48개 창에서 재생성 순번과 방식 ID에 따른 위치를 선택합니다. 45개 전체의 무작위 추첨이나 독립적인 확률 시뮬레이션이 아닙니다. 제한된 후보를 순환하므로 영원히 새로운 조합이 나온다고 보장하지 않습니다.

## 5. 설정과 결과 확인

**설정 → 기기 및 서비스 → Lotto 6/45 Analysis → 구성**의 추천 설정에서 방식을 복수 선택합니다. 개인 사주 방식은 별도 사주정보 입력·수정을 먼저 완료하고, 중앙값 방식은 다른 로컬 방식 2개 이상과 함께 선택합니다. 기간·반감기·가중치는 현재 코드의 고정값이며 일반 설정 화면에서 개별 편집하는 옵션은 없습니다.

[기본 선택값](../custom_components/lotto_645/methods.py)은 위상잔차 그래프, 전이·간격 위상, 가중 빈도, 동반출현쌍, 종합 앙상블입니다. 이는 제품의 초기 구성이지 성능 순위가 아닙니다. AI 추천은 17개 로컬 방식과 별개이며 중앙값에도 포함되지 않습니다.

```yaml
action: lotto_645.refresh
```

이 수동 동작은 로컬 추천을 재생성하고 기존 AI 추천은 유지합니다. 실제로 보관할 구매번호는 별도로 등록해야 합니다.

각 추천 센서의 속성 또는 `추천 요약`의 `games`에서 다음 정보를 확인합니다. 엔티티 ID는 설치 환경과 사용자 이름 변경에 따라 달라지므로 고정 ID를 가정하지 않습니다.

| 속성 | 읽는 방법 |
|---|---|
| `method_id`, `method_description` | 어떤 방식인지 확인 |
| `score`, `score_meaning` | 후보 적합도와 의미. 0.8을 80% 당첨률로 해석하지 않음 |
| `number_feature_weights` | 정규화된 번호 단계 비중 |
| `number_feature_scores` | 최종 선택 번호별 특징 점수. 전체 45개의 원시 관측값 목록은 아님 |
| `score_components`, `score_component_weights` | 조합 요소별 점수·정규화 비중·별도 감점 |
| `gaps_since_last`, `number_sum`, `odd_count`, `low_count_1_22` | 선택 조합의 간격과 형태 |
| `latest_draw_overlap`, `exact_past_first_prize_match` | 직전 겹침 수와 과거 완전일치 여부 |
| `generation_sequence` | 수동 재생성 순번 |

## 6. 예시와 검증의 범위

개별 문서의 숫자 예시는 **계산을 설명하기 위한 가상 입력 또는 수학적으로 도출한 값**입니다. 실제 특정 회차의 통계, 추천번호, 백테스트 결과가 아닙니다. 최종 번호는 모든 후보의 순위·조합 점수·제외 조건이 함께 결정하므로 단일 예시만으로 재현할 수 없습니다.

[검증 안내](VALIDATION.md)는 출력 조건과 계산 규칙 검증을, [로컬 리뷰 안내](LOCAL_REVIEWS.md)는 추첨 전 저장 추천의 사후 평가를 설명합니다. 표본 수·평가 시점·공식 확인 여부를 함께 읽어야 합니다. 같은 이력으로 여러 방식을 만들어 비교한다고 독립적인 증거가 17개 생기는 것은 아닙니다.
