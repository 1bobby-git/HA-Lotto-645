# 공개 공식 · 핫넘버

[17개 방식 목록](../../README.md#추천-방식-17종) · [공통 계산 원리](../FORMULAS.md)

`method_id: hot_numbers` · 분류: 공개 분석식 · 후보 풀: **22개**

## 1. 어떤 방식인가요?

최근에 자주 등장한 번호와 최근 출현 강도가 상대적으로 올라간 번호를 우선합니다. 단순히 직전 당첨번호 6개를 그대로 재사용하거나 최근 출현 횟수 상위 6개를 그대로 고르는 방식은 아닙니다.

이 문서에서 ‘핫’은 최근 관찰 특징을 뜻합니다. 다음 회차 당첨 가능성이 높다고 확인된 번호라는 뜻이 아닙니다.

## 2. 사용하는 데이터와 계산

본번호 기준 최근 10·30회의 표준화 출현 잔차를 구하고, 변화 방향은 `z30-z120`으로 계산합니다. 각 지표를 45개 번호 안에서 평균 순위로 변환합니다.

```text
최근 상승 지표 = R(z30-z120)
```

내부 키 이름은 `phase_velocity_positive`이지만, **음수 값을 0으로 잘라내지 않습니다.** 실제로는 부호 있는 변화량을 순위화합니다. 상승량이 큰 번호가 높은 점수를 받고, 변화가 음수인 번호도 다른 번호와의 상대적 위치에 따라 점수를 받습니다.

## 3. 번호 단계 가중치

| 내부 키 | 의미 | 원시 가중치 |
|---|---|---|
| `frequency_10` | 최근 10회 출현 강도 | 0.44 |
| `frequency_30` | 최근 30회 출현 강도 | 0.34 |
| `phase_velocity_positive` | 30회와 120회 잔차의 부호 있는 차이 | 0.22 |

전체 빈도 특징은 이 번호 가중치에 직접 들어가지 않습니다. 다만 전체 이력은 공통 번호쌍 계산과 과거 조합 제외 등에 사용됩니다.

## 4. 조합 단계 가중치

| 내부 키 | 의미 | 원시 가중치 |
|---|---|---|
| `individual` | 선택 번호 점수 평균 | 0.66 |
| `pair` | 내부 번호쌍 연결 | 0.10 |
| `diversity` | 내부 변화 방향·간격 다양성 | 0.05 |
| `balance` | 조합 형태 균형 | 0.08 |

합계 0.89로 정규화한 뒤 공통 유사성 감점을 적용합니다. 최근 강도가 높은 번호라도 직전 번호와 과하게 겹치는 조합은 감점될 수 있습니다.

## 5. 계산 예시

가상 번호 A의 정규화 점수가 `0.9,0.8,0.7`이라면:

```text
0.44×0.9 + 0.34×0.8 + 0.22×0.7 = 0.822
```

가상 번호 B가 최근 10회에서는 높지만 30회와 변화 방향에서 낮으면, 최근 한 구간의 빈도만으로 A보다 높게 평가되지는 않을 수 있습니다. 0.822는 후보 적합도이며 실제 출현률 82.2%가 아닙니다.

## 6. 설정과 결과 확인

통합 **구성 → 추천 설정**에서 선택합니다. 개인정보나 AI 연결 없이 사용합니다. 최근 10·30회 및 비교 기준 120회는 현재 고정 설정입니다.

`number_feature_scores`에서 세 특징을 확인하고 `number_feature_weights`, `score_components`, `latest_draw_overlap`을 함께 읽으세요. 공통 속성 `phase_leaders`는 변화의 **절댓값** 순위이므로 핫넘버의 상승 방향과 완전히 같은 순위라고 보면 안 됩니다. 방향은 `phase_velocity_positive` 특징을 기준으로 해석합니다.

## 7. 차이와 해석의 한계

[가중 빈도](weighted_frequency.md)는 전체·100회까지 직접 반영하고, [콜드·미출현](overdue_gap.md)은 긴 미출현 간격에 초점을 둡니다. 두 방식이 반대 번호를 내더라도 하나가 틀렸다는 뜻은 아닙니다. 애초에 선택 기준이 다릅니다.

최근 빈도는 작은 표본의 우연한 편차에 민감합니다. 연속 출현이 이어진다거나 핫넘버가 다음 회차에도 유리하다는 보장은 없습니다. 각 번호 조합의 당첨 확률은 이 이름이나 점수로 바뀌지 않습니다.
