# 균등 공식 · 조합보정 층화 CCSS

[24개 공식 목록](../../README.md#추첨-공식-24종) · [공통 계산 원리](../FORMULAS.md)

`method_id: calibrated_stratified` · 분류: 균등 추첨 공식 · 후보 풀: **45개**

## 1. 어떤 공식인가요?

1–10 / 11–20 / 21–30 / 31–40 / 41–45 구간별 추가 개수 x를 정할 때 가능한 조합 개수만큼 가중합니다. 그 뒤 각 구간 안에서 균등하게 뽑습니다.

## 2. 계산 원리

```text
W(x)=∏ C(n_j,x_j), P(x)=W(x)/C(n,r); 개별 조합 확률=P(x)/W(x)=1/C(n,r)
```

운영 환경의 난수원은 `secrets.SystemRandom`입니다. 테스트에서만 고정 seed를 주입합니다. 번호합·홀짝·연속수·과거 빈도로 후보를 다시 정렬하거나 점수를 매기지 않습니다. 첨부 연구의 균등 비복원추출 또는 CCSS 설계를 구현했습니다.

## 3. 계산 예시

**가상으로** 고정번호가 7, 21이면 나머지 43개 중 4개를 뽑습니다. 제외 조건이 없을 때 완성 조합 수는 `C(43,4)=123,410`이고 각 조합의 생성 확률은 그 역수입니다. 이것은 실제 추첨에서 해당 한 게임이 당첨될 확률과는 다른 개념입니다. 고정번호는 현재 엔진 API와 테스트에서 지원하며 일반 옵션 화면에는 입력 필드를 추가하지 않았습니다.

## 4. 현재 컴포넌트의 제외 조건

기존 정책인 **과거 1등 완전일치 제외**, 같은 배치의 동일 게임 제외, 재생성 직전 조합 제외를 유지합니다. 따라서 컴포넌트가 표시하는 것은 전체 8,145,060개가 아니라 **제외 후 허용 공간에서의 조건부 균등성**입니다. 제외 없이 호출한 순수 엔진만 전체 공간에서 균등합니다. 제외가 많으면 정확한 조합 인덱스 보정으로 전환하고, 모두 제외되면 명시적인 오류를 반환합니다.

과거 당첨번호도 다시 나올 수 있습니다. 이 제외 정책과 여러 게임의 다양성은 한 게임의 당첨확률을 높이지 않습니다. 더 작은 홀짝·번호합 범위를 강제하지 않습니다.

## 5. 설정·저장·한계

추첨 공식 선택 목록에서 선택합니다. `formula_id`, `formula_version`, `rng`, `uniformity`, `eligible_combination_count`를 확인할 수 있습니다. 적합도 점수는 `null`이며 0점으로 해석하지 않습니다. 재시작은 저장된 번호를 유지하고 명시적인 재생성·회차·설정 변경 때 새로 추첨합니다. 균등 공식의 실제 추천번호도 다른 로컬 공식과 함께 선택하면 선택 공식 중앙값 집계에 포함됩니다.

모든 특정 6개 조합의 실제 1등 확률은 공정·독립 추첨 아래 **1/8,145,060**입니다. 생성기 균등성 검증은 실제 로또의 공정성 인증이나 당첨 예측 검증이 아닙니다.
