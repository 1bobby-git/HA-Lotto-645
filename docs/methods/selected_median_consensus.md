# 합의 추천 · 선택 공식 중앙값

[12개 대표 공식 목록](../../README.md#추첨-공식-12종) · [공통 계산 원리](../FORMULAS.md)

`method_id: selected_median_consensus` · 분류: 선택 공식 집계 · 후보 풀: **0개** (점수형 후보 풀 미사용)

## 1. 어떤 공식인가요?

**선택한 다른 로컬 공식 센서에 표시되는 실제 6개 추천번호**가 입력입니다. 각 게임을 오름차순 정렬하고 첫 번째 번호끼리, 두 번째 번호끼리, … 여섯 번째 번호끼리 중앙값을 계산합니다. 각 중앙값의 **±1 범위**에서 1~45의 서로 다른 정수 6개를 구성합니다.

공식 버전 2부터 내부 45개 적합도 점수 중앙값을 사용하지 않습니다. 한 중앙값 주위에 6개를 몰아넣는 계산도 아닙니다. 기존 `selected_median_consensus`와 엔티티 ID는 유지합니다.

## 2. 선택 조건과 포함 범위

구성의 **추첨 공식** 항목에서 이 공식과 **다른 로컬 공식 2개 이상**을 선택합니다. 균등 추첨 6종, 베이지안 실험 공식, 기존 점수형 공식 모두 집계할 수 있습니다. 명리는 선택되어 있고 개인 사주 설정이 준비된 경우에 참여합니다.

자기 자신, 별도 기능인 Home Assistant AI, 당첨번호·요약·진행률 센서는 집계하지 않습니다. 선택을 해제한 공식도 제외합니다. 잘못된 번호나 다른 대상 회차의 추천은 무시하며, 유효한 원본이 2개 미만이면 합의 추천은 `unavailable`이 됩니다. 유효한 입력이 복구되면 자동 계산합니다.

## 3. 순번별 중앙값 ±1

```text
M[j] = median(선택 공식마다 정렬한 추천번호의 j번째 값), j=1..6
후보[j] = 1..45 중 abs(번호 - M[j]) <= 1인 정수
최종 후보 = 후보[1] × ... × 후보[6] 중 엄격한 오름차순 조합
```

짝수 개 입력이면 가운데 두 값의 평균을 사용합니다. 중앙값이 10.5이면 10·11만 허용하고 9·12는 허용하지 않습니다. 순번별 최대 3개, 전체 최대 729개 조합만 검사합니다. 난수나 점수형 후보 풀은 사용하지 않습니다.

후보 중 과거 1등 조합과 현재 기여 공식의 동일 조합을 제외하고, **중앙값과의 총 거리 최소 → 원본 번호 지지표 합 최대 → 작은 조합 순**으로 하나를 결정합니다. ±1 안에 유효 후보가 없으면 `no_candidate_within_tolerance` 상태로 대기하며 범위를 임의로 확장하지 않습니다. 내부 점수나 리뷰 성적을 가중치로 사용하지 않습니다.

## 4. 자동 갱신

원본 추천 센서와 패널은 동일한 coordinator 데이터를 사용합니다. 새 원본 추천 데이터가 게시될 때 합의 추천을 먼저 계산하고 **원본·합의·요약·패널이 같은 결과를 보도록 한 번에 게시**합니다. 별도 새로고침, 이력 다운로드, AI 호출 또는 원본 공식 재생성은 요청하지 않습니다.

- 원본 공식의 실제 추천번호가 변경되면 자동 재계산합니다.
- 공식을 추가·제거하고 설정을 저장하면 자동 다시 로드 과정에서 새 선택 목록을 반영합니다. 확인 전 선택 화면의 임시 편집은 반영하지 않습니다.
- 시간·설명·리뷰 점수만 변경되거나 동일 데이터가 재게시되면 기존 합의번호와 갱신시각을 유지합니다.
- 일반 새로고침도 원본번호가 실제로 바뀐 경우에만 새 집계 결과를 만듭니다. 합의번호 자체를 임의로 다시 뽑지 않습니다.

입력이 달라져 재계산되어도 중앙값과 최종 조합이 같을 수 있습니다. 이 경우 번호는 유지되며 입력 목록·서명·갱신시각으로 반영 여부를 확인합니다. Home Assistant 개발자 도구에서 임시로 덮어쓴 상태 문자열이 아니라 통합이 게시한 추천 데이터가 원본입니다.

## 5. 계산 예시

두 공식을 선택했고 각 센서의 추천번호가 다음과 같다고 가정합니다. 각 줄은 오름차순으로 정렬되어 있습니다.

```text
공식 A:  2, 10, 18, 26, 34, 42
공식 B:  4, 12, 20, 28, 36, 44

중앙값:  3, 11, 19, 27, 35, 43
```

**같은 순번의 번호끼리 계산합니다.** 첫 번째 번호는 `(2 + 4) / 2 = 3`, 두 번째는 `(10 + 12) / 2 = 11`이며, 같은 계산을 여섯 번째 `(42 + 44) / 2 = 43`까지 반복합니다. 두 공식이므로 각 순번의 두 값 평균이 중앙값입니다. 모든 번호 12개를 한꺼번에 모아 중앙값 하나를 구하는 계산이 아닙니다.

위 중앙값 조합이 과거 1등·현재 기여 공식의 중복 조합이 아니라면 **3, 11, 19, 27, 35, 43을 그대로 추천**합니다. 제외 조건에 걸리면 각 순번의 중앙값 ±1 안에서 대안을 찾습니다. 예를 들어 첫 번째 순번의 후보는 `2·3·4`, 두 번째는 `10·11·12`입니다. 무조건 1을 더하거나 빼는 것이 아니라 중앙값에 가장 가까운 유효 조합을 우선합니다.

공식 A 또는 B의 추천번호가 바뀌거나 참여 공식을 추가·제거하고 설정을 저장하면 이 계산을 자동으로 다시 수행합니다. 입력이 같으면 결과를 유지하며, 입력이 달라도 중앙값과 최종 조합이 같을 수 있습니다. 이 예시는 계산 설명용이며 실제 당첨 예측이나 성능 우위 예시가 아닙니다.

## 6. 센서 속성 읽기

| 속성 | 의미 |
|---|---|
| `consensus_source_method_ids` / `consensus_source_methods` | 현재 기여한 공식의 ID와 이름 |
| `consensus_source_numbers` | 기여 공식별 실제 입력 6개 번호 |
| `consensus_source_count` | 유효한 기여 공식 수 |
| `consensus_missing_source_method_ids` | 선택했지만 유효한 현재 번호가 없는 공식 |
| `consensus_position_medians` | 순번별 중앙값 6개 |
| `consensus_position_deviations` | 최종 번호에서 중앙값을 뺀 값; 모두 -1~+1 |
| `consensus_tolerance` | 허용 거리 1 |
| `consensus_input_signature` | 입력번호·선택·대상회차·제외 이력의 변경 확인용 서명 |
| `consensus_updated_at` | 집계 입력이 마지막으로 변경되어 반영된 시각 |
| `formula_version` | 2. 이전 기록은 점수 중앙값 버전이며 소급 변경하지 않음 |
| `consensus_status` | 번호가 없을 때 원본 부족/유효 후보 부재 상태 |

이전 버전의 `consensus_number_median_scores`와 `consensus_number_score_spread`는 숫자 중앙값과 다른 값이므로 새 결과에 노출하지 않습니다. `analysis_score`도 부여하지 않습니다. 집계 생성시각을 별도 저장하여 나중에 만든 합의번호를 원본 센서의 오래된 생성시각에 소급하여 당첨·리뷰 판정하지 않습니다.

## 7. 한계

중앙값 ±1은 여러 추천번호를 종합하는 개인화 규칙이지 미래 추첨의 확률 모델이 아닙니다. 어떤 공식도 실제 당첨 확률을 높인다는 보장은 없습니다. 추천번호의 ±1 근접은 실제 당첨 판정에서 일치로 인정되지 않습니다.
