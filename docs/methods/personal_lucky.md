# 재미 공식 · 개인 행운 번호

[추첨 공식 목록](../../README.md#추첨-공식-24종) · [공통 계산 원리](../FORMULAS.md)

`method_id: personal_lucky` · 후보 풀: **45개**

## 계산 원리

별명·키워드를 NFKC와 공백 정규화로 처리합니다. 최대 80자로 제한하고 제어문자를 거절합니다. 알고리즘 버전, 테마, 키워드, 대상 회차, 매 생성마다 새로운 256비트 난수를 JSON으로 직렬화합니다. SHA-256 카운터 스트림의 정수 거부 추출로 나머지 연산 편향을 피하고 부분 Fisher–Yates로 6개를 선택합니다.

꿈·소망 테마도 자체 문자열 변환입니다. 전통 해몽 사전이나 운세 예측이 아니며 생년월일은 요구하지 않습니다. 같은 입력이어도 재생성은 새 난수를 사용합니다. 사용자용 시드 입력은 없고 재시작은 기존 캐시의 실제 번호를 복원합니다. 과거 1등·같은 배치 중복을 제외하며 한 게임의 당첨 확률을 높이지 않습니다.

## 계산 예시

`  나의   소망 `은 `나의 소망`으로 정규화됩니다. 키워드 `돼지꿈`, 테마 `꿈 키워드`는 로컬 변환의 입력일 뿐 돼지에 특정 당첨 번호가 정해져 있다는 뜻이 아닙니다. 새로고침 후 새 결과, 재시작 후 기존 캐시 결과가 표시됩니다.

## 설정·개인정보

**구성 → 개인 행운 번호 설정**에 별명 또는 키워드와 테마를 저장하고 추천 설정에서 선택합니다. 원문은 HA 구성 옵션에만 저장하며 로그·센서 속성·AI 프롬프트에는 넣지 않습니다. `lucky_theme`, `entertainment_only`, `personal_input_exposed`만 설명 속성으로 표시합니다. HA 백업에는 구성 옵션이 포함될 수 있으므로 개인정보 대신 별명을 권합니다. 점수는 null이며 수익·예측 확률을 표시하지 않습니다.

## 구현 근거

[지락실의 개인 입력 기반 선택](https://www.jiraksil.com/service/lotto)은 제품 아이디어 참고입니다. `personal_lucky.py`의 버전이 지정된 독립 변환을 사용하며 외부 서비스를 호출하지 않습니다. 동일 알고리즘의 복제가 아닙니다.
