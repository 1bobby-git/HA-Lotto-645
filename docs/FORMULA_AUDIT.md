# 추천식 계산 검증 — v1.6.0

**계산 구현의 검증과 당첨 예측력 검증은 다르다.** 아래는 코드와 공식의 대응·제약조건·재생성 동작을 검증한 기록이다. 특정 방식이 미래 당첨확률을 높인다는 결론은 없다.

## 수정한 공통 오류

1. **동점 순위 편향**: 값이 같은 번호에도 번호순으로 다른 점수를 주던 `_rank01`을 평균순위로 수정했다. 전체가 동점이면 모두0.5다. 최종 후보가 동점일 때 정렬을 재현하기 위한 번호순 비교는 유지하지만 이를 분석 근거로 표시하지 않는다.
2. **베이지안 수축 소실**: 사후평균을 다시 순위화하면 사전분포의 수축 폭이 지워졌다. 이제 `Beta(6,39)`에 최근60회 관측을 더한 평균에서 `6/45`를 뺀 값을 `.5+.5*tanh(잔차/(6/45))`로 변환하여 수축 폭을 남긴다. 이는 후보 점수 변환이지 보정된 당첨확률이 아니다.
3. **이월수 과대 가중**: 임의의 0/1/2/3개 이월 점수 대신 정확한 초기하분포 `C(6,k)C(39,6-k)/C(45,6)`를 최빈 집단 확률로 나눠 쓴다. 집단에 조합이 많이 포함된다는 뜻이지 한 장의 당첨확률이 높다는 뜻은 아니다.
4. **구간 정의 불일치**: 후보 풀과 균형 평가를 1–10,11–20,21–30,31–40,41–45로 통일했다.
5. **완전 중복 재등장**: 다양성 제약을 완화하는 최후 경로에서도 같은 포트폴리오/과거1등/해당 방식의 직전 추천과 완전히 같은 조합은 금지한다. 수동 재생성 시 이전 조합을 엔진에 전달한다.
6. **무제한 후보 메모리**: 후보마다 세부 사전을 전부 쌓지 않고 상위1,200개만 heap에 유지한다. 실제 선택한 조합의 상세 점수만 다시 계산한다. 검색 대상은 기존 후보 풀의 전체6개 조합이다.
7. **점수/개인정보 분리**: 모든 방식 가중치를 정규화하고 최종 점수를0~1로 제한한다. 미선택 명리 프로필 오류가 일반 방식을 막지 않게 분리했다. 비활성 메서드의 빈 목록을 기본5개로 되살리지 않는다.

## 실제 이력 기반 점검

`python scripts/audit_methods.py --rounds 12 --workers 4`

1~1240회 번들 이력의 마지막12회(1229~1240회)를 대상으로, 각 대상 회차 **직전 회차까지만** 엔진에 전달했다.16종을 같은 고정 순서로 실행한192게임에 대해 6개 정수/범위/과거 완전일치 제외/포트폴리오 완전중복 제외/유한 정규화 점수를 확인했다. 명리에는 저장소의 **합성 테스트 프로필**만 사용했다. 사용자 개인정보는 사용하지 않았다.

전체 결과·번호·기준회차·이력SHA-256은 `validation-v1.6.0.json`에 남겼다. 이 자료는 이미 알려진 이력에 대한 **회고적 소표본 점검**이며 사전등록된 전향적 시험이나 독립 검증표본이 아니다. 같은 회차의16게임은 독립 표본으로 합쳐 취급할 수 없다. 표본 성적에 따라 방법이나 가중치를 다시 선택하지 않았고, 방법 간 우열 순위/당첨확률 상승 결론도 내리지 않았다.

모든 고정6개 조합의 공정 추첨1등 확률은 `1/C(45,6) = 1/8,145,060`이며, 한 게임에서 본번호와 겹치는 개수의 기대값은0.8개다. 추첨 공정성 자체를 이 테스트로 감사한 것은 아니다.

## 유지한 운영 조건

- GitHub 공유 미러/로컬 캐시/번들 seed 우선. 동행복권 직접 요청은 기본OFF.
- 직접 수집을 켜도 요청 간격·예산·403/429 차단 회로를 유지한다.
- 수동 번호 재생성은 AI를 호출하거나 기존 AI 결과를 다시 생성하지 않는다.
- AI 번호의 불리언·소수·무한대·문자열을 정수로 강제 변환하던 경로를 거절하도록 수정했다.
- 개인 사주 원본뿐 아니라 사주 추천의 파생 근거도 AI 프롬프트에 넣지 않는다.
- 릴리스는 main의 Validate 성공 이후 해당 정확한 커밋에서만 발행한다. 이전 태그를 이동하지 않는다.
