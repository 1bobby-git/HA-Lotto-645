# 유료 Actions 없는 배포와 완료 기준

모든 구현·수정은 변경 범위에 필요한 확인을 마친 뒤 GitHub Release와 HACS 배포, 실제 적용 확인까지 진행한다. 코드를 작성하거나 커밋한 것만으로 완료 처리하지 않는다.

## 배포 순서

1. 승인된 변경을 정확한 Git 커밋으로 고정한다. 작업 폴더의 사용자 자료·자격정보가 섞이지 않도록 한다.
2. 필요한 대상 검사만 수행한다. 광범위한 반복 검증·테스트 행렬은 자동으로 돌리지 않는다.
3. 컴포넌트 `manifest.json`과 릴리스 버전을 맞춘다. `git archive <commit>:custom_components/lotto_645`로 HACS용 `lotto_645.zip`을 생성한다.
4. 빌드 커밋·SHA-256을 기록하고 GitHub CLI로 Draft에 업로드한다. 업로드한 파일과 대상 커밋을 확인한 뒤 릴리스를 공개한다. 이미 발행된 태그를 덮어쓰지 않는다.
5. HACS에서 해당 버전을 실제 설치하고 HA에서 기능·데이터 보존을 확인한다. 실패 시 이전 배포물과 백업으로 복원하며 정상 완료로 보고하지 않는다.

공개 HA와 비공개 Core의 배포물을 혼합하지 않는다. Core/API 실행 파일은 비공개 저장소와 운영 서버에만 둔다. GitHub-hosted Actions 결제·한도 상향 없이 인증된 NUC에서 검사·빌드·GitHub CLI 발행을 수행한다.

`prepare_local_release.py`는 개발용 ZIP 준비 도구이며 정상 작동 확인이나 정식 배포를 대신하지 않는다. GitHub/HACS 실제 배포 버전과 HA 설치 버전을 최종 결과에 명시한다.
