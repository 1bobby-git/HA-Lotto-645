# 조건 생성·다중 조합·개인화 사용법

## 어디에서 사용하나요?

로컬 공식은 기본 카탈로그 22개와 기존 연구 확장 2개, 총 24개입니다. 기존 기본 선택과 저장 ID를 변경하지 않습니다. Home Assistant AI와 미구매 다중 조합 설계는 이 수에 포함하지 않습니다.

통합 **구성 → 조건 지정 생성 설정**에 고정·제외·형태 조건을 저장한 뒤 추천 설정에서 **조건 지정 균등 생성**을 선택합니다. 개인 행운 번호도 구성에서 키워드를 저장한 뒤 선택합니다. 계열별 다수결은 기존 중앙값과 별개로 선택합니다. 두 합의 방식은 서로를 입력으로 사용하지 않습니다.

**로또 복권 → 한눈에 → 다중 조합 설계**에 후보 6~45개와 게임 수 1~5개를 지정합니다. 저장 조건 적용은 기본 켜짐입니다. 해제하면 그 요청에만 저장 조건을 사용하지 않습니다. 과거 1등과 현재 추천의 완전 일치 조합은 항상 제외합니다. 조건 불일치·게임 부족이면 오류를 내고 예산이나 조건을 몰래 바꾸지 않습니다.

## 세 가지 다중 조합 설계 모드

**번호 배분**은 후보 번호 사용 횟수 제곱합의 증가를 줄이며 동률이면 새 3수 묶음이 많은 후보를 고릅니다. **3수 커버리지**는 그 우선순위를 뒤집습니다. 후보 공간이 작으면 전부, 크면 최대 4,096개 후보를 비교하는 탐욕적 설계이며 전역 최적화를 보장하지 않습니다. 막힌 탐욕 탐색은 수학적 불가능 증명이 아닙니다.

**9후보 3게임 휠링**은 후보 9개를 서로 겹치지 않는 세 묶음 A·B·C(각 3개)로 나누고 A∪B, A∪C, B∪C를 만듭니다. 280개 분할을 검사해 저장 조건·기존 조합 제외·게임 간 중복 한도를 지키는 분할에서 선택합니다. 9개 후보·정확히 3게임을 사용자가 직접 선택해야 하며 자동으로 게임 수를 바꾸지 않습니다. 모든 후보가 두 게임에 등장하므로 1개 이상 고정번호를 모든 게임에 강제하면 허용 분할이 없습니다. 게임 사이에는 항상 3개가 겹칩니다.

예시 A={1,2,3}, B={4,5,6}, C={7,8,9}는 구조 설명이며 추천 번호가 아닙니다. 후보 안에 본번호 4개가 있으면 126가지 모두에서 한 게임 이상 3개 일치, 본번호 6개가 있으면 84가지 모두에서 한 게임 이상 4개 일치입니다. 기존 8후보 4게임 휠링은 별도 유지합니다.

## 검증 표시를 읽는 법

`number_coverage`는 사용한 번호 수, `pair_coverage`·`triple_coverage`는 서로 다른 번호쌍·세 번호 묶음의 개수입니다. 당첨률이 아닙니다. `conditional_min_match[r]`는 후보에 본번호 r개가 포함된 **조건** 아래 한 게임 이상에서 얻는 최소 일치 수입니다. 이는 후보군 자체가 맞는다는 보장이 아닙니다.

요청 결과에 대해 가능한 후보 내 적중 집합을 20,000경우까지 전수 검사합니다. 초과하면 `verification_complete=false`, `conditional_min_match={}`, `counterexample_count=null`로 표시합니다. 완료 시 `counterexample_count=0`은 계산해 표시한 최소 하한에 대한 반례가 없다는 의미이며 임의의 당첨 목표 달성을 뜻하지 않습니다. 미구매 미리보기를 수정하거나 게임을 빼면 원래 하한을 그대로 사용할 수 없습니다. 서로 다른 b게임의 1등 확률 b/C(45,6)는 어떤 배분 방식이든 같습니다.

## 기록·개인정보·실행 한계

미리보기는 구매·리뷰·실제 추천·AI 데이터를 쓰지 않습니다. 관리자로 인증된 WebSocket만 처리하며 통합별 동시 작업 1개, 제한된 후보/검증 수, 20초 대기 한도를 사용합니다. 계산은 executor에서 실행합니다. 입력이나 통합을 바꾸면 늦게 도착한 화면 결과는 버립니다.

과거 회차 검증에는 선택 회차 이전 이력과 **현재 저장한 조건·현재 키워드**만 사용합니다. 현재 추천 캐시나 대상/미래 번호는 생성 입력으로 쓰지 않습니다. 실제로 당시 저장한 예측이 아니라 현재 공식의 재실행입니다. 키워드는 HA 구성 옵션에 로컬 저장하고 로그·센서·AI에 전달하지 않습니다. 꿈 테마는 자체 문자열 변환이며 전통 해몽 사전이 아닙니다. 새 공식은 출현 확률 개선을 주장하지 않습니다.
