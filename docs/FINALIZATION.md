# 최종 번호 산출 · 후보 커버링 재조합

## 사용 순서
일반 공식을 먼저 생성한다. 선택된 N개 공식이 같은 배치에서 전부 정상 저장되면 `최종 번호 산출`이 준비된다. 한눈에의 준비 상태 버튼에서 추천 리뷰의 2단계 패널로 이동한다. 출력 게임 수 B를 확인하고 버튼을 직접 눌러 실행한다.

18개는 예시다. 입력 집합 전체를 기다리며 일부가 미지원·실패·동의 미충족이면 조용히 제외하지 않는다. 설정한 원본 공식과 최종 산출은 별개이며 일반 공식 재생성·센서 갱신·당첨 발표가 최종 산출을 자동 실행하지 않는다.

B는 기본 N, 최대 20과 기존 생성 이용 한도 중 작은 값이다. 모든 후보를 유지해야 하므로 후보 37개는 최소 7게임이 필요하다. 불가능한 B에서는 실행하지 않으며 후보를 임의로 없애거나 B를 자동 증가시키지 않는다.

## 상태와 결과 보존
입력의 준비 상태와 최종 작업 상태를 나누어 표시한다. 새 원본이 생성돼도 선택한 완결 배치와 기존 최종 결과는 유지한다. `새 입력 사용`으로 바꾸고 다시 실행해야 새 묶음이 만들어진다. 실패/취소 결과도 이력으로 남으며 같은 입력의 의도적 추가 실행을 별도로 선택할 수 있다.

네트워크 오류 후에는 저장한 같은 요청을 조회한다. 재시작이나 화면 갱신이 새 요청을 만들지 않는다. 응답이 불명확한 요청을 취소하면 늦게 도착한 같은 키의 요청도 서버에서 막는다.

## 기존 기능과의 구분
기존 원본 pending·nonce·재시도·추천 리뷰·복권·엔티티 ID는 유지한다. 추가 네이티브 버튼은 패널과 같은 서버 검사를 거친다. 작은 진단 센서는 상태·완료 개수·생성 시각·게임 수만 제공한다. 큰 번호/지표를 recorder에 반복 저장하지 않는다.

최종 결과를 내 복권에 자동 저장하지 않는다. 사용자가 실제 번호를 등록하고 번호·회차가 일치할 때만 bundle/game 출처를 연결하며, 다음 재생성으로 연결을 바꾸지 않는다. 구매 복권 행과 원본 공식 평가를 섞지 않는다.

## 지원 범위
계산은 비공개 Formulab Core에서만 수행한다. HA 릴리스에는 알고리즘·Core·JEV 키가 없다. HA 로컬 AI 결과는 최초 버전 입력으로 지원하지 않는다. 서버가 출처를 확인할 수 없는 이전 캐시는 새 원본 생성이 필요하다.

과거 연구 재현은 로또랩에서만 수행·노출한다. HA는 실사용 대상의 저장된 묶음과 실제 발표 후 대조를 표시한다. 같은 회원으로 연결된 웹과 HA는 같은 live bundle/game ID·번호·순서 계약을 사용한다.

후보 커버리지는 실험적 방식이다. 합성 표본의 3수/4수 커버리지나 부분집합 수는 당첨 보장·동일 게임 수의 1등 확률 향상이 아니다. 원본 N과 출력 B가 다른 경우 원본 최고 성적은 직접 우열 비교하지 않는다.

## 릴리스 후보
2.4.0 후보는 검증·승인 전 단계다. 새 HACS 태그를 덮어쓰거나 사용자 HA에 자동 설치·재시작하지 않는다. 2.3.4로 내릴 경우 기존 복권 읽기는 호환되지만 새로운 최종 출처 정보를 보존하려면 복권 편집은 2.4.0 복구 후 수행한다.
