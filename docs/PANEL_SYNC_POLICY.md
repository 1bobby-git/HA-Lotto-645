# 로또 패널 동기화 정책

## 추천번호와 당첨 결과는 별개입니다

`recommendations`는 현재 코어가 생성하여 센서에 표시한 실제 번호입니다. `winning`은 추첨 전에 저장한 추천과 발표된 결과의 대조입니다. 이번 주 생성번호가 아직 추첨 전이더라도 한눈에의 현재 추천 목록에 표시합니다. 이전 회차 결과나 구매번호를 현재 추천으로 대신 표시하지 않습니다.

## 변경 즉시 갱신

관리자로 인증된 `lotto_645/subscribe`는 해당 통합의 `entry_id`만 담은 변경 알림을 구독합니다. 코디네이터의 추천·AI·구매·결과 갱신과 통합 재로드 완료 후 알림을 보냅니다. 패널은 `lotto_645/purchases_get`으로 HA의 저장된 현재 상태만 읽습니다. 개인 번호·키워드는 알림에 넣지 않습니다.

초기 읽기와 구독 사이의 누락을 막기 위해 구독 등록 직후 다시 읽습니다. 같은 작업 중 여러 알림은 하나로 합치고, 재연결·화면 복귀 때 갱신합니다. 통합 전환이나 화면 종료 전에 시작한 응답은 버립니다. 편집 중인 구매번호·회차·저장 리비전은 상태 갱신으로 덮어쓰지 않습니다. 종료 시 구독·재시도 타이머를 해제하며 재진입 시 다시 연결합니다.

통합 재로드 중 일시적으로 사용할 수 없는 상태는 최대 5회, 2초 간격으로 재확인합니다. 구독 자체의 연결 실패는 5초 후 재시도하며 화면 종료 시 중단합니다. 최초 접속·원래 버전의 브라우저 캐시에서는 버전별 Custom Element 이름과 모듈 주소를 사용하여 새 동기화 코드를 실행합니다.

## 추첨 결과 확인 주기

평일에 추첨 결과용 타이머가 쉬어도 위 변경 알림은 계속 동작합니다. 토요일 20:30~일요일 10:30 KST의 결과 대기 또는 공식 대조 대기에서는 60초마다 HA 내부 상태를 확인합니다. 그 외에는 고정 30초 폴링을 하지 않습니다. 화면이 숨겨지면 주기 타이머를 중단합니다. 추첨 시간 계산은 KST를 기준으로 합니다.

`다시 확인` 버튼만 사용자가 명시적으로 결과 수집을 요청하는 동작입니다. 변경 알림을 받거나 `purchases_get`을 호출했다고 동행복권·GitHub를 다시 조회하는 것은 아닙니다. 실제 외부 이력 수집은 백엔드의 공유 미러·제한된 폴백 정책을 따릅니다.

## 기존 정보 유지

구매번호 등록·QR·당첨 대조·실제 리뷰·센서 ID·2단 헤더와 입력 초안은 유지합니다. 과거 재실행은 Lotto Lab에서 수행하며 HA 패널에는 실행 경로가 없습니다.
