# v1.10.0 · 내 추천 기록의 별점, 결과 분리, 당첨 상세

## 어디서 보는가

- **기존 Lotto 6/45 Analysis 기기**: 일반 센서 영역에는 선택한 공식별 추천번호와 AI 추천번호만 남습니다. 제어 영역은 번호 재생성·AI 생성 버튼, 진단 영역은 추천 요약·공식 안내·사주 프로필입니다.
- **로또 추첨·당첨 결과 기기**: `n회 추첨번호`, `내 구매번호`, 새 `binary_sensor`의 `n회 당첨 상세`를 모았습니다. `추첨 결과 지금 확인`은 제어 버튼입니다. 기존 `n회 당첨 여부`와 `최신 당첨 결과` 센서는 호환성을 위해 유지하되 이 기기의 진단 영역으로 이동합니다.
- **왼쪽 메뉴 → 로또 복권**: 구매번호/QR 입력, 추첨 결과, 공식별 당첨 내역과 누적 리뷰를 한 화면에서 확인합니다. 번호를 편집하는 동안에도 결과·리뷰는 갱신되며 입력값/저장 리비전을 덮어쓰지 않습니다.

HA 기본 기기 화면은 엔티티 도메인·분류에 따라 영역을 결정하므로 임의 제목의 기본 카드나 `기기 정보` 필드를 만들어 넣지 않습니다. 관련 결과를 별도 논리 기기로 묶고 정적 설명은 진단 분류를 사용합니다. 기존 엔티티의 unique_id는 변경하지 않으며 사용자가 직접 지정한 이름은 존중합니다. 직접 이름을 지정한 추천 센서는 자동 별점 이름 대신 그 사용자 이름이 우선할 수 있습니다. `local_review` 속성과 로또 복권 화면에서는 항상 점수를 확인할 수 있습니다.

## 별점은 예측 확률이 아니다

예: `★4.0 · 80.0점 | 공개 공식 · 가중 빈도`는 **이 HA에 실제 저장됐던 추천의 공식 확인 회차 평균 리뷰가 80점**이라는 뜻입니다. 당첨 확률 80%, 사용자 구매 성공률 80%, 검증된 예측력, 다른 사용자 전체의 평가를 뜻하지 않습니다. 표본 수 `reviewed_rounds`를 같이 제공합니다.

공식 확인된 기록이 없으면 `☆평가대기`입니다. 속보만 있으면 `★… · …점(잠정)`을 표시합니다. 이미 누적 공식 별점이 있는 경우 센서명은 그 평균을 유지하고 이번 속보 점수는 `latest_provisional`과 전용 화면에서 분리해서 봅니다.

### 점수 정의 — 사용자의 사후 비교를 위한 명시적 응용 규칙

게임마다 추천6개와 본번호6개를 정렬하여 다음을 계산합니다. 보너스는 공식 등수에만 쓰고 리뷰의 ±1 기준에는 넣지 않습니다.

1. **정확 일치 E**: 두 집합의 교집합 개수.
2. **±1 일대일 일치 N**: 정확히 일치한 숫자를 양쪽에서 제거한 뒤, 남은 숫자들 사이의 차이가 정확히1인 대응을 최대한 찾습니다. 같은 당첨번호를 두 추천번호가 중복 사용하지 못하고 45↔1 순환도 없습니다.
3. **전체 거리 D**: 정렬된 각 순번의 절대 차이 합계. 수직선상 일대일 최소거리이며 1~45에서 중복 없는6개 집합의 최대 거리는234입니다.

`회차 점수 = 80×E/6 + 15×(E+N)/6 + 5×(1−D/234)`

가중치 80/15/5는 이 기능의 공개된 설계값입니다. 수학적 당첨 예측 공식으로 주장하지 않습니다. 전부 정확하면100점·★5, 전부±1이어도 정확 일치가 없으면20점 이하이고 **미당첨**입니다. 전체 거리는 미세 비교용으로만 작은 비중을 가집니다. 각 항목 점수와 ±1 대응 쌍을 공개합니다.

`누적 별점 = 공식 확인된 회차 점수의 산술평균 / 20`

점수 합계·회차 수·평균·최고 등수·정확/±1 누계·최근12회 요약도 속성에 제공합니다. 이번 회차 순위는 저장된 공식 사이의 상대 순위이며 동점은 공동 순위입니다. 결과를 보고 가중치를 자동으로 바꾸거나 최고점을 얻을 때까지 재생성한 번호를 채택하지 않습니다.

## 어떤 번호를 누적하는가

- 이 HA에서 실제 생성·저장되었고 **해당 회차 추첨 예정 시작 전의 생성시각**이 있는 번호만 사용합니다.
- 공식당 회차별 **마지막 유효한 추첨 전 번호 1게임**입니다. 같은 회차를 여러 번 조회·새로고침해도 평가 수는 늘지 않습니다.
- 선택했다가 나중에 해제한 공식도 이미 저장된 그 회차의 기록은 남습니다. AI도 유효한 실제 생성시각이 있으면 같은 기준을 씁니다. 직접 구매번호는 추천 알고리즘의 리뷰에 섞지 않습니다.
- 예전 당첨 이력을 보고 과거 추천을 다시 만들어 채우지 않습니다. 업데이트 전에 저장된 실제 스냅샷은 생성시각이 확인될 때만 가져옵니다. 없거나 늦은 기록은 평가 대기/제외이며0점이나 미당첨 표본으로 넣지 않습니다.
- 단일/복수 언론 속보 점수는 잠정이며 누적 평균에 넣지 않습니다. 출처 충돌 시 잠정 점수를 철회하고 확인을 기다립니다. 공식 결과 수신 후 동일 회차를 한 번 확정하고, 공식 정정이 오면 기존 회차 결과를 **교체**합니다. 표본을 하나 더 추가하지 않습니다.

리뷰 원자료는 별도 로컬 Store `lotto_645.reviews.<entry_id>`에 저장합니다. 재시작 후 복원하고, 손상 시 원본을 덮어쓰지 않습니다. 쓰기 실패는 저장 대기를 표시하고 재시도하며 추천/구매 데이터와 분리합니다. 사주 원본과 QR 영수증 식별값을 리뷰 파일에 저장하지 않습니다. 원자료를 외부 AI·미러에 전송하지 않습니다.

## 바이너리 당첨 상세

`binary_sensor`의 상태는 하나 이상의 실제 등수 당첨이 있으면 `on`, 비교할 게임이 있고 전부 미당첨이면 `off`, 결과 대기·출처 충돌·비교할 번호 없음이면 `unknown`입니다. 기존 문자 요약 센서도 유지합니다.

주요 속성:

- `round`, `winning_numbers`, `bonus_number`, `result_verification`, `provisional`
- `winning_game_count`, `highest_prize`, `recommendation_game_count`, `purchased_game_count`
- `results`: 모든 추첨 공식/구매A~E의 번호·정확일치수·맞은번호·보너스일치·등수·원본 엔티티 ID
- `winners`, `losers`: 당첨/미당첨 상세 목록
- 각 추천 행의 `review`: 해당 회차 점수·별점·정확/±1·근접쌍·회차 순위. 등수와 별도입니다.

1등6개, 2등5개+보너스, 3등5개, 4등4개, 5등3개의 정확 일치 규칙은 변경하지 않습니다. 추천번호 당첨과 실제 구매번호 당첨을 구분하며, 실제 소유권이나 지급 확인 기능이 아닙니다. 속보 상태의 판정은 반드시 `provisional`과 출처 상태를 확인해야 합니다.

## 기존 작업의 완료/제한

방송 예정 시각부터 HA 시계로 공개 RSS를 약60초 간격으로 확인하는 기능, 독립 QR 카메라/사진/주소 입력 화면, A~E 명시적 저장, 원래23개 추첨 공식·사주 입력·AI 재생성 분리는 유지합니다. 현재 공식 `qr.dhlottery.co.kr` 주소, 빈 칸 `n000000000000`, 식별부10/18자리 형식을 추가로 검증하며 식별부는 버립니다. 실제 방송 종료 감지나 10분 내 게시/수신 보장은 아닙니다.

실제 운영 HA·사용자의 휴대폰/복권에 대한 종단간 실사용 시험은 별도로 필요합니다. 테스트는 순수 로직, 실제 HA 클래스/저장소/설정, Chromium의 합성 QR·저장·편집 보존·리뷰 표시를 대상으로 합니다.

이 브랜치에 있는 main 보호 JSON은 **가져오기용 설정 파일일 뿐 실제 GitHub 보호 적용을 뜻하지 않습니다**. 관리 권한 연결 없이 이를 적용했다고 보고하지 않습니다. 이전 원본 로고 바이너리 교체도 별도 상태를 확인해야 하며 새 로고를 생성하거나 색을 줄여 대신하지 않습니다.
