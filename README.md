# HA-Lotto-645

Home Assistant용 **로또 6/45 전체 회차 분석 · 선택형 번호 추천 · Home Assistant AI 추천** 커스텀 통합입니다.

> 로또 추첨은 독립적인 무작위 사건입니다. 아래 방식은 과거 데이터를 분류하거나 조합 후보를 고르는 휴리스틱일 뿐이며 당첨을 보장하거나 실제 당첨 확률을 높이지 않습니다. 모든 6개 조합의 1등 확률은 동일하게 **1 / 8,145,060**입니다.

## v1.2.0 주요 기능

- 동행복권 **1회부터 최신 확정 회차까지** 1등 본번호 6개 동기화
- 최초 전체 동기화 후 Home Assistant `.storage`에 캐시, 이후 새 회차만 증분 동기화
- **추천 방식을 여러 개 동시 선택** 가능
- 선택한 방식마다 **6개 번호 1게임 + 핵심 근거 + 세부 점수** 생성
- 과거 1등 본번호 6개와 완전히 동일한 조합 자동 제외
- 게임 간 번호가 지나치게 반복되지 않도록 다양성 제약 적용
- **공식 탐색 ③ = 공개공식 종합형**을 기본 추천 방식으로 제공
- **명리 권장 = 60갑자 일진 + 하도(河圖) 수리오행** 방식 추가 및 기본 선택
- Home Assistant **AI Task** 기반 AI 추천 1게임 지원
- 설정 > AI에서 선택한 기본 데이터 생성 AI를 그대로 사용하거나 특정 `ai_task` 엔티티 지정 가능
- AI 결과도 1~45 범위, 중복, 과거 1등 완전일치, 로컬 추천 완전복제를 다시 로컬 검증
- 6시간마다 최신 회차 확인 + 즉시 새로고침 버튼/서비스
- AI 자동 생성은 사용량·비용 가능성을 고려해 기본 비활성화
- Config Flow / Options Flow / HACS 지원

## 선택 가능한 추천 방식

설치 후 **설정 → 기기 및 서비스 → Lotto 6/45 Analysis → 구성**에서 여러 방식을 동시에 선택할 수 있습니다. 선택한 순서대로 추천 게임 센서가 생성됩니다.

| 방식 | 분류 | 핵심 기준 |
|---|---|---|
| 독창 패턴 ① | 독창 분석 | 장·단기 잔차 위상 + 다음 회차 전이 + 번호쌍 그래프 |
| 독창 패턴 ② | 독창 분석 | 전이 + 미출현 간격 + 시간축 곡률 |
| 공개 공식 · 가중 빈도 | 공개 분석식 | 최근 10·30·100회 + 전체 빈도 가중 |
| 공개 공식 · 핫넘버 | 공개 분석식 | 최근 출현 상승세 중심 |
| 공개 공식 · 콜드·미출현 | 공개 분석식 | 미출현 간격을 완화 가중 |
| 공개 공식 · 동반출현쌍 | 공개 분석식 | 전체 + 최근 120회 번호쌍 잔차 |
| 공개 공식 · 균형 필터 | 공개 분석식 | 번호합·홀짝·저고·번호대 분산 |
| 공개 공식 · 델타 시스템 | 공개 분석식 | 오름차순 번호 사이 간격과 반복·범위 |
| 공개 공식 · 이월수 | 공개 분석식 | 직전 회차 이월수 + 전이 점수 |
| **공식 탐색 ③ · 공개공식 종합형** | **추천 공개 분석식** | **가중 빈도·간격·동반출현·균형·델타·이월수 종합** |
| **명리 권장 · 일진 오행·하도 수리** | **전통 명리 권장** | **다음 추첨일 60갑자 일진 + 일간·지지 오행 + 하도 수리오행 + 오행·음양 균형** |

### 공개 공식 권장안

공개된 로또 분석 규칙 중 어느 하나도 미래 추첨 확률을 높인다고 검증된 공식은 없습니다. 따라서 한 가지 규칙을 강하게 적용하기보다 **서로 성격이 다른 공개 필터를 합의 점수로 결합**한 `공식 탐색 ③ · 공개공식 종합형`을 공개 분석식 권장안으로 사용합니다.

### 명리 권장안

명리/역술 계열은 임의의 현대식 행운번호표 대신 전통적으로 계산 규칙이 명확한 다음 두 체계를 결합합니다.

- **60갑자 일진(日辰)**: 다음 추첨 예정일의 일주를 계산하고 천간(日干/Day Master)과 지지 오행을 사용
- **하도(河圖) 수리오행**: 1·6 수, 2·7 화, 3·8 목, 4·9 금, 5·0 토

다음 추첨일의 일진과 각 번호의 오행 관계를 계산한 뒤 오행 분산, 음양(홀짝) 균형, 특정 오행 과집중 억제와 기존 통계 점수를 함께 반영합니다.

`1949-10-01 = 갑자(甲子)` 기준점을 회귀 테스트에 포함해 60갑자 계산을 검산합니다. 다만 여기서 **검증**은 전통 계산 규칙을 재현·검산할 수 있다는 의미이며, 명리학이나 수리오행이 로또 당첨 확률을 높인다는 과학적 검증은 없습니다.

상세 계산식은 [`docs/FORMULAS.md`](docs/FORMULAS.md)를 참고하세요.

## 독창 분석 구조

기본 독창 분석은 단순 빈도·홀짝·합계만으로 고르지 않습니다.

1. **장기-단기 잔차 위상**
   - 전체, 최근 260/120/30회의 출현을 기대값 대비 표준화합니다.
   - 장기 방향과 최근 변화 방향의 충돌 및 변화 속도·곡률을 계산합니다.
2. **다음 회차 전이 점수**
   - 최신 당첨번호가 과거에 나온 뒤 다음 회차에서 어떤 번호가 등장했는지 표준화합니다.
3. **번호쌍 그래프**
   - 45개 번호의 990개 쌍에 대해 전체 + 최근 120회 동시출현 잔차를 계산합니다.
4. **미출현 간격**
   - 현재 간격을 이론적 기대 간격과 비교하되 극단값은 제한합니다.
5. **과거 조합 거리**
   - 과거 1등 완전 동일 조합을 제외하고 반복되는 4개/5개 코어와 최신 회차 과도 중복을 감점합니다.

## Home Assistant AI 추천

이 기능은 Home Assistant의 **AI Task 데이터 생성 기능**을 사용합니다. 외부 AI API를 통합 코드가 별도로 호출하지 않습니다.

1. Home Assistant **설정 → AI**에서 `데이터 생성 작업` 제공자를 설정합니다.
2. Lotto 6/45 Analysis의 **구성**에서 `Home Assistant AI 추천 사용`을 켭니다.
3. `AI Task 엔티티`를 비워 두면 Home Assistant에서 선택한 기본 데이터 생성 AI를 사용합니다.
4. 특정 AI Task를 사용하려면 해당 `ai_task.*` 엔티티를 선택합니다.
5. `AI 추천 생성` 버튼 또는 `lotto_645.generate_ai_recommendation` 서비스를 실행합니다.

AI에는 기준 회차, 위상 변화 상위, 다음 회차 전이 상위, 번호쌍 그래프 상위와 현재 로컬 추천을 전달합니다. AI가 반환한 결과는 다시 다음 조건으로 검증합니다.

- 1~45 정수 정확히 6개
- 번호 중복 없음
- 과거 1등 6개 본번호와 완전 동일하지 않음
- 현재 로컬 추천 게임과 완전히 동일하지 않음
- 핵심 근거가 비어 있지 않음
- 실패하면 최대 1회 재시도

AI 자동 생성은 새 회차 확인 때마다 AI 제공자 사용량 또는 비용을 발생시킬 수 있으므로 기본값은 꺼져 있습니다.

## 설치

### HACS 사용자 저장소

1. HACS → Integrations → Custom repositories
2. `https://github.com/1bobby-git/HA-Lotto-645` 추가
3. Category: `Integration`
4. 설치 후 Home Assistant 재시작
5. 설정 → 기기 및 서비스 → 통합 구성 요소 추가 → **Lotto 6/45 Analysis**
6. 추가 후 통합의 **구성**에서 원하는 추천 방식과 AI 사용 여부 선택

### 수동 설치

`custom_components/lotto_645` 폴더를 HA의 `/config/custom_components/lotto_645`에 복사한 뒤 Home Assistant를 재시작합니다.

## 엔티티

기본적으로 다음 엔티티가 생성됩니다.

- `추천 요약`
- 선택한 방식별 추천 센서
- `최신 당첨 결과`
- `즉시 새로고침`
- AI 사용 시 `AI 추천`
- AI 사용 시 `AI 추천 생성`

실제 `entity_id`는 Home Assistant의 언어 및 기존 엔티티 이름에 따라 달라질 수 있습니다.

### 명리 추천 센서 속성 예시

```yaml
method_id: myungri_hetu_day_pillar
label: "명리 권장 · 일진 오행·하도 수리"
method: "전통 명리 권장"
target_draw_date: "2026-09-12"
sexagenary_day: "..."
day_master: "..."
day_master_element: "..."
number_five_elements:
  "1": "수"
  "8": "목"
five_element_counts:
  목: 1
  화: 1
  토: 1
  금: 1
  수: 2
traditional_method: "60갑자 일진(日柱) + 하도(河圖) 수리오행"
exact_past_first_prize_match: false
```

위 값은 **속성 구조 예시**이며 실제 일진과 추천번호는 설치 시점의 최신 공식 추첨일 기준으로 계산합니다.

## 서비스

공식 데이터 즉시 확인:

```yaml
action: lotto_645.refresh
```

기본 HA AI Task로 AI 추천 생성:

```yaml
action: lotto_645.generate_ai_recommendation
```

특정 AI Task 지정:

```yaml
action: lotto_645.generate_ai_recommendation
data:
  ai_task_entity_id: ai_task.google_ai_task
```

## 데이터 갱신

- 기본 확인 주기: 6시간
- 최초 설치: 1회~최신 회차 전체 동기화 후 `.storage` 캐시
- 이후: 최신 회차 번호만 확인하고 새 회차가 있을 때 증분 수집
- 동행복권 일시 장애 시: 마지막 정상 캐시를 유지하고 `source_status: cached_fallback` 표시
- 선택 방식 변경 시: 통합 재로드 후 같은 전체 회차 데이터로 새 방식만 다시 계산
