# HA-Lotto-645

## v1.9.0 · 회차 표시와 직접 구매 5게임 대조

**추첨번호 센서 이름이 `n회 추첨번호`로 표시**됩니다. 기존 entity_id는 유지됩니다. `추천 요약` 값은 추천 대상 회차이며, `games`에는 선택한 방식별 번호와 근거가 들어 있습니다. 당첨 점수나 실제 추첨 결과를 뜻하지 않습니다.

**구성 → 직접 구매번호 입력·수정 → 복권 회차 → A~E**에서 게임당6개 번호를 최대5게임 저장할 수 있습니다. 쉼표/공백 또는 번호당두자리 12자리 입력을 정규화하고, 다른 회차를 지우지 않고 HA 로컬에 보관합니다. 저장은 AI나 추천 재생성을 실행하지 않습니다.

`내 구매번호`는 마지막 입력 회차의 게임별 결과를, `당첨 여부`는 최신 수신 회차의 추천·AI·구매번호 결과를 구분해 표시합니다. 미래 회차는 대기, 미등록은 미등록이며 미당첨으로 처리하지 않습니다. 실제 구매·지급을 확인하는 서비스는 아닙니다.

**v1.8.1 수동 결과 갱신은 그대로 유지**합니다. 새 추첨 결과를 받으려면 `즉시 새로고침 · 번호 재생성`을 누르세요. 기존추천 스냅샷과 대조하고 구매번호는 바꾸지 않습니다.

## v1.8.1 · 수동 새로고침 기반 추첨번호·당첨 판정

## v1.8.0 · 추첨번호 및 자동 당첨 판정

- **추첨번호**: 최신 확정 회차의 본번호 6개를 상태로 표시하고 보너스번호·회차·추첨일을 속성으로 제공합니다.
- **당첨 여부**: 해당 회차 추첨 전에 생성되어 저장된 모든 로컬 추천 센서와 Home Assistant AI 추천(존재하는 경우)을 실제 결과와 비교합니다. 1등=6개, 2등=5개+보너스, 3등=5개, 4등=4개, 5등=3개로 판정하며 센서별 당첨/미당첨과 일치번호를 속성에서 확인할 수 있습니다.
- 추천 결과는 새 추첨 결과가 들어오면서 다음 회차용 번호로 바뀌기 **전에 스냅샷으로 저장**되므로 직전 회차 판정이 유실되지 않습니다.
- 토요일 20:30~22:30(KST)에는 5분 간격으로 공유 미러 갱신을 확인합니다. 각 HA 설치가 동행복권을 반복 크롤링하지 않으며 직접 폴백은 기존처럼 사용자가 명시적으로 켠 경우만 제한적으로 사용합니다.

## v1.7.0 · 선택 방식 중앙값 합의 추천

`합의 추천 · 선택 방식 중앙값`을 추가했습니다. 사용자가 함께 선택한 **다른 로컬 추천 방식 2개 이상**의 1~45 번호별 0~1 적합도를 모아 각 번호의 **중앙값(median)** 을 계산하고 중앙값이 높은 번호들로 6개 조합을 만듭니다. 한 방식의 극단값이 전체를 끌고 가지 않게 하는 강건 집계 방식입니다. AI 추천은 집계하지 않으며, 명리 방식은 사용자가 함께 선택했을 때만 포함합니다.

단순히 각 추천게임의 1번째·2번째 번호를 위치별로 평균/중앙값 내지 않습니다. 그런 계산은 존재하지 않는 인공 번호를 만들 수 있으므로, **각 방식이 1~45 각각에 부여한 내부 적합도의 중앙값**을 사용합니다. 센서 속성에서 참여 방식, 번호별 중앙값, 방식 간 점수 범위, 최종 추천에서 받은 지지표 수를 확인할 수 있습니다. 이 합의 점수 역시 당첨 확률이 아닙니다.



## v1.6.0 · 제공 사주 규칙 적용 및 공식 검증

개인 명리 추천을 **십신10종·지장간 비율·월령/통근/투간·격국 후보·억부/조후/통관/병약·대운/세운/월운/일시운·합충형파해**로 확장했습니다. 잘못된 일진 기준일표는 교정하고 표 사이의 불일치는 별도로 표시합니다. 계산 규칙의 재현과 당첨 예측력은 구분합니다.

`구성 → 명리 사주정보 입력·수정`에서 양/음력·음력 기준(한국/중국)·생년월일·시간·성별·출생지·시간대를 저장합니다. 시간은 `14:30` 또는 `미상`으로 입력하며, 미상일 때 시주를 만들지 않습니다. 기존 음력 사용자의 중국력 변환은 자동으로 바꾸지 않습니다.

동점 순위 편향, 베이지안 수축 소실, 이월수 점수, 중복 후보 fallback, 원치 않는 명리 분석 의존성을 수정했습니다. 점수는 0~1 **적합도**이며 확률이 아닙니다. 번호별 점수/가중치와 명리 근거를 센서에서 확인할 수 있습니다. 큰 명리 상세정보는 실시간 속성으로 제공하되 Recorder 중복 저장에서 제외해 DB 부담을 줄입니다.

- [명리 규칙·원문 교정·점수 가정](docs/SAJU_RULES.md)
- [전체 공식 검증 범위와 한계](docs/VALIDATION.md)
- [실제 과거 회차 재생 결과](docs/formula-audit-results.json)

## v1.5.2 · 명리 입력 화면 및 추천 방식 안내 개선

- `Unknown error occurred`가 반복되던 **2단계 Options Flow를 제거**했습니다.
- 이제 `구성` 화면 한 페이지에 **추천 방식 + [명리] 개인 사주정보 + AI + 데이터 소스**가 모두 표시됩니다.
- `명리 권장 · 개인 사주 원국·대운·추첨일`을 선택한 경우에만 [명리] 필수정보 검증을 수행하며, 누락 시 같은 화면에서 어떤 입력이 필요한지 알려줍니다.
- `추천 방식 안내` 센서의 `16`은 점수나 추천번호가 아니라 **지원하는 추천 방식 수**였습니다. v1.5.2부터 상태를 `16개 추천 방식`으로 표시합니다.
- `추천 방식 안내`는 로또 데이터 갱신 실패와 무관한 정적 정보이므로 네트워크/미러 장애 때도 `사용할 수 없음`으로 바뀌지 않습니다.
- 각 추천번호 센서의 속성에 `method_category`, `method_description`을 추가해 해당 방식의 의미를 바로 확인할 수 있습니다.

### 명리 사주정보 입력 위치

```text
설정
→ 기기 및 서비스
→ Lotto 6/45 Analysis
→ 구성
→ 같은 화면의 [명리] 항목에 입력
```

입력 항목은 **양력/음력, 생년월일, 출생시간, 성별, 출생지, IANA 시간대**입니다. 음력 윤달과 선택적인 진태양시(경도+균시차) 보정도 지원합니다. 명리 방식을 선택하지 않았다면 [명리] 항목은 비워도 됩니다.

> 개인 출생정보는 Home Assistant 구성에 로컬 저장되며 공유 로또 미러에 전송되지 않습니다. Home Assistant AI 추천에도 원본 생년월일·출생시간·출생지를 넣지 않습니다.

### 추천 방식 안내 보는 방법

`추천 방식 안내`의 상태는 **지원 방식 개수**입니다. 각 방식의 전체 설명은 엔티티 속성의 `methods`에 저장됩니다. Home Assistant 기본 팝업에서 속성이 접혀 보이면:

```text
개발자 도구 → 상태 → 추천 방식 안내 엔티티 선택
```

에서 `methods` 목록을 확인할 수 있습니다. 또한 실제로 선택한 각 추천번호 엔티티에는 `method_description` 속성이 추가되어 그 방식의 상세 원리를 바로 볼 수 있습니다.

## v1.5.0 · 개인 사주 명리 고도화

`명리 권장 · 개인 사주 원국·대운·추첨일`은 **사주정보 입력 전에는 실행되지 않습니다.** 입력 후 연주·월주·일주·시주, 일간, 오행 강약, 지장간, 십신, 납음, 12운성, 대운을 계산하고 다음 추첨일 20:35의 사주와 천간합·충, 지지합·충·해·형을 비교합니다. 번호는 하도 수리오행에 매핑해 보완오행/십신 역할/대운·추첨일 관계를 주 점수로 사용하고 기존 로또 통계는 보조 점수로만 사용합니다.

> 명리 해석은 전통 문화 체계의 재현 가능한 휴리스틱이며 당첨 확률 상승이 과학적으로 검증된 것은 아닙니다.

Home Assistant용 **로또 6/45 전체 회차 분석 · 선택형 번호 추천 · 명리 추천 · Home Assistant AI 추천** 커스텀 통합입니다.

> 로또 추첨은 독립적인 무작위 사건입니다. 모든 6개 조합의 1등 확률은 동일하게 **1 / 8,145,060**입니다. 이 통합의 통계·명리 방식은 조합 선택용 휴리스틱이며 당첨을 보장하거나 실제 당첨 확률을 높인다고 주장하지 않습니다.
