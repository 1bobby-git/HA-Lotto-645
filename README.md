# HA-Lotto-645

Home Assistant용 **로또 6/45 전체 회차 분석 · 선택형 번호 추천 · 명리 추천 · Home Assistant AI 추천** 커스텀 통합입니다.

> 로또 추첨은 독립적인 무작위 사건입니다. 아래 방식은 과거 데이터를 분류하거나 조합 후보를 고르는 휴리스틱이며 당첨을 보장하거나 실제 당첨 확률을 높이지 않습니다. 모든 6개 조합의 1등 확률은 동일하게 **1 / 8,145,060**입니다.

## v1.3.0 핵심 변경

### 동행복권 차단 위험을 줄인 수집 구조

각 Home Assistant 설치가 동행복권 사이트에서 1회부터 최신 회차까지 반복 크롤링하던 구조를 제거했습니다.

기본 데이터 흐름은 다음과 같습니다.

```text
동행복권 공식 결과
       ↓ 소수의 검증 요청만 사용
GitHub Actions 중앙 미러 갱신
       ↓
data/lotto645-history.json
       ↓
각 Home Assistant 설치
       ↓
HA .storage 캐시
```

- HA 런타임 기본 수집처: **이 저장소의 GitHub 공유 이력 미러**
- HACS 릴리스에 `history_seed.json`을 함께 포함하므로 GitHub 미러가 잠시 실패해도 최초 설정 가능
- 중앙 미러 갱신은 토요일 22:50 KST 및 일요일 09:30 KST 예비 실행
- 중앙 갱신은 전체 이력을 매번 동행복권에서 긁지 않고 공개 GitHub 역사 데이터셋을 벌크 전송용으로 사용한 뒤 **최신 회차를 동행복권과 교차 검증**
- 동행복권 공식 요청은 순차 실행, 최소 3초 간격, 실행당 최대 4회
- HTTP 403/429 발생 시 즉시 중단하며 우회·프록시 회전·CAPTCHA 회피를 하지 않음
- HA에서 동행복권 직접 요청은 **기본 OFF**
- 사용자가 직접 폴백을 켜더라도 공유 미러 장애 시 최근 최대 1~2개 누락 회차만 제한적으로 확인
- 직접 폴백으로 전체 회차를 수집하는 코드는 사용하지 않음
- 공유 미러는 SHA-256과 1회~최신 연속성, 번호 범위, 중복 및 보너스 번호를 검증

따라서 일반 사용자는 동행복권에 직접 접근하지 않아도 됩니다.

## 기존 기능 유지

v1.3.0은 기존 요청 기능을 제거하지 않습니다.

- **1회부터 최신 확정 회차까지** 본번호 6개 분석
- 보너스 번호는 추천 번호 선정에서 제외
- 과거 1등과 완전히 같은 6개 조합 자동 제외
- 추천 방식 여러 개 동시 선택
- 방식별 6개 번호 + 핵심 근거 + 세부 점수
- 동일 데이터/동일 설정에서 같은 결과를 내는 결정적 분석
- 추천 게임끼리 과도한 번호 중복 억제
- 6시간 자동 확인 및 `즉시 새로고침`
- Home Assistant AI Task 추천
- 60갑자·하도 수리오행 명리 추천
- HACS 및 Config Flow/Options Flow

## 번호 추천 방식

**설정 → 기기 및 서비스 → Lotto 6/45 Analysis → 구성**에서 여러 방식을 함께 선택할 수 있습니다.

| 방식 | 분류 | 핵심 |
|---|---|---|
| 독창 패턴 ① | 독창 분석 | 장·단기 잔차 위상 + 다음 회차 전이 + 번호쌍 그래프 |
| 독창 패턴 ② | 독창 분석 | 전이 + 미출현 간격 + 시간축 곡률 |
| 공개 공식 · 가중 빈도 | 공개 분석식 | 최근 10·30·100회 + 전체 빈도 가중 |
| 공개 공식 · 핫넘버 | 공개 분석식 | 최근 출현 상승세 |
| 공개 공식 · 콜드·미출현 | 공개 분석식 | 미출현 간격의 완화 가중 |
| 공개 공식 · 동반출현쌍 | 공개 분석식 | 전체 + 최근 120회 번호쌍 잔차 |
| 공개 공식 · 균형 필터 | 공개 분석식 | 번호합·홀짝·저고·번호대 분산 |
| 공개 공식 · 델타 시스템 | 공개 분석식 | 인접 번호 간격·반복·범위 |
| 공개 공식 · 이월수 | 공개 분석식 | 직전 회차 이월수 + 전이 |
| **공식 탐색 ③ · 공개공식 종합형** | **추천 공개 분석식** | **빈도·간격·동반출현·균형·델타·이월수 종합** |
| **명리 권장 · 일진 오행·하도 수리** | **전통 명리 권장** | **다음 추첨일 60갑자 일진 + 하도 수리오행 + 오행·음양 균형** |

기본 권장 선택은 `독창 패턴 ①`, `독창 패턴 ②`, `가중 빈도`, `동반출현쌍`, `공개공식 종합형`, `명리 권장`입니다.

상세 계산식은 [`docs/FORMULAS.md`](docs/FORMULAS.md)를 참고하세요.

## 명리 권장 방식

현대식 임의 행운번호표 대신 계산 규칙이 명확한 전통 체계를 사용합니다.

- 다음 추첨 예정일의 **60갑자 일진(日辰)** 계산
- 일간(日干/Day Master)과 지지의 오행
- 하도(河圖) 수리오행: `1·6 수 / 2·7 화 / 3·8 목 / 4·9 금 / 5·0 토`
- 오행 분산, 음양 균형, 특정 오행 과집중 억제
- 통계 점수를 보조적으로 결합

여기서 “검증”은 전통 계산 규칙을 재현·검산할 수 있다는 뜻이며 명리학이 로또 당첨 확률을 높인다는 과학적 검증을 뜻하지 않습니다.

## Home Assistant AI 추천

외부 API를 통합 코드가 직접 호출하지 않고 Home Assistant의 **AI Task 데이터 생성 기능**을 사용합니다.

1. Home Assistant **설정 → AI**에서 데이터 생성 작업 제공자를 선택합니다.
2. 통합의 **구성**에서 `Home Assistant AI 추천 사용`을 켭니다.
3. `AI Task 엔티티`를 비워 두면 HA의 기본 데이터 생성 AI를 사용합니다.
4. 특정 `ai_task.*` 엔티티를 직접 지정할 수도 있습니다.
5. `AI 추천 생성` 버튼 또는 아래 서비스를 실행합니다.

```yaml
action: lotto_645.generate_ai_recommendation
```

특정 AI Task 지정:

```yaml
action: lotto_645.generate_ai_recommendation
data:
  ai_task_entity_id: ai_task.google_ai_task
```

AI 결과는 저장 전 다음을 다시 검증합니다.

- 1~45 정수 정확히 6개
- 중복 없음
- 과거 1등 6개와 완전 동일하지 않음
- 현재 로컬 추천과 완전 동일하지 않음
- 핵심 근거 존재
- 실패 시 최대 1회 재시도

## 데이터 수집 옵션

`동행복권 제한적 직접 폴백 허용`은 기본값이 **꺼짐**입니다.

끄기 권장 이유:

- 공유 GitHub 미러와 번들 이력만으로 정상 분석 가능
- 각 HA 인스턴스가 동행복권 서버에 직접 요청할 필요가 없음
- 사이트의 접근 제한 및 순간적인 부하 영향을 줄임

직접 폴백을 켜도 **공유 미러가 실패한 경우에만**, 그리고 **최근 최대 2개 누락 회차**만 확인합니다.

## 데이터 출처와 검증

- 원출처: 동행복권 로또 6/45 공식 결과
- 런타임 배포 미러: 이 저장소 `data/lotto645-history.json`
- 릴리스 번들 폴백: `custom_components/lotto_645/history_seed.json`
- 벌크 역사 데이터 운반용 보조 자료: `Utopia-ZEN/hotnumber`
- 최신 회차는 중앙 갱신 작업에서 동행복권 결과와 교차 검증

보조 자료는 공식 원출처를 대체하는 신뢰 선언이 아니라, 동행복권에 대량 요청을 보내지 않기 위한 **벌크 전송 수단**입니다. 최신 데이터가 공식 결과와 불일치하면 미러 갱신을 중단해 기존 정상 미러를 유지합니다.
