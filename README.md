# HA-Lotto-645

Home Assistant용 **로또 6/45 전체 회차 분석 · 선택형 번호 추천 · 명리 추천 · Home Assistant AI 추천** 커스텀 통합입니다.

> 로또 추첨은 독립적인 무작위 사건입니다. 모든 6개 조합의 1등 확률은 동일하게 **1 / 8,145,060**입니다. 이 통합의 통계·명리 방식은 조합 선택용 휴리스틱이며 당첨을 보장하거나 실제 당첨 확률을 높인다고 주장하지 않습니다.

## v1.4.0 주요 개선

- 모바일/Retina 환경에서 깨지던 브랜드 이미지를 Home Assistant 권장 규격의 `logo.png`, `logo@2x.png`, `icon.png`, `icon@2x.png`로 다시 생성
- **즉시 새로고침 · 번호 재생성**을 누르면 최신 이력을 확인한 뒤 선택된 **비AI 추천만 새 후보로 재생성**
- 수동 재생성 시 기존 Home Assistant AI 추천은 그대로 유지하고 AI 자동 호출도 억제
- 추천 방식 **16종**으로 확대
- `독창 패턴 ①/②`, `공식 탐색 ③`처럼 붙던 숫자 표기 제거
- `추천 방식 안내` 센서 추가: 모든 방식의 이름·분류·상세 원리를 Home Assistant에서 확인 가능
- 구성 화면의 각 추천 방식 선택 항목에도 계산 원리를 함께 표시
- 기존 공유 미러 우선 수집, 과거 당첨조합 제외, 명리 추천, HA AI Task 기능 유지

## 데이터 수집: 동행복권 차단 위험 최소화

각 Home Assistant 설치가 동행복권에서 1회부터 최신 회차까지 반복 크롤링하지 않습니다.

```text
동행복권 공식 결과
       ↓ 중앙 작업에서 최신 회차 소수 검증
GitHub 공유 이력 미러
       ↓
각 Home Assistant
       ↓
HA .storage 캐시
```

기본 경로는 **HA 로컬 캐시 → GitHub 공유 미러 → 릴리스 번들 스냅샷**입니다.

- 중앙 미러: `data/lotto645-history.json`
- 릴리스 번들: `custom_components/lotto_645/history_seed.json`
- 중앙 갱신: 토요일 22:50 KST, 일요일 09:30 KST 예비 실행
- 공유 데이터는 1회부터 최신 회차 연속성, 번호 범위, 중복, 보너스 및 SHA-256 검증
- HA의 동행복권 직접 폴백은 **기본 OFF**
- 직접 폴백을 켜도 공유 미러 장애 때 최근 최대 2회만 확인
- 직접 요청은 순차 처리, 최소 3초 간격, 실행당 최대 4회
- HTTP 403/429 시 즉시 중단하고 12시간 회로 차단
- 프록시 회전, CAPTCHA 우회, IP 회피를 사용하지 않음

## 번호 추천 방식

**설정 → 기기 및 서비스 → Lotto 6/45 Analysis → 구성**에서 여러 방식을 동시에 선택할 수 있습니다. 각 방식은 6개 번호 1게임과 핵심 근거·세부 점수를 생성합니다.

| 추천 방식 | 분류 | 계산 아이디어 |
|---|---|---|
| 독창 패턴 · 위상잔차 그래프 | 독창 분석 | 장기 빈도와 최근 변화 방향의 충돌, 변화 속도, 전이, 번호쌍 그래프 |
| 독창 패턴 · 전이·간격 위상 | 독창 분석 | 직전 번호의 다음 회차 전이, 미출현 간격, 시간축 곡률 |
| 독창 패턴 · 다중시간대 공명 | 독창 분석 | 10·30·120·260회 및 전체 변화의 공통 신호와 전이·그래프 결합 |
| 공개 공식 · 가중 빈도 | 공개 분석식 | 최근 10·30·100회와 전체 빈도의 가중 합 |
| 공개 공식 · 핫넘버 | 공개 분석식 | 최근 출현 강도와 상승세 중심 |
| 공개 공식 · 콜드·미출현 | 공개 분석식 | 현재 미출현 간격을 상한 처리해 장기 미출현 과집중 완화 |
| 공개 공식 · 동반출현쌍 | 공개 분석식 | 전체 + 최근 120회 번호쌍 동시출현 잔차 |
| 공개 공식 · 삼중 동반출현 | 공개 분석식 | 세 번호가 같은 회차에 함께 나온 구조 + 번호쌍 보정 |
| 공개 공식 · 지수감쇠 최근성 | 공개 분석식 | 최근 회차일수록 높은 가중치, 과거로 갈수록 반감기 방식 감쇠 |
| 공개 공식 · 베이지안 수축 | 공개 분석식 | 최근 60회 출현률을 전체 평균 6/45 쪽으로 수축해 작은 표본 극단 완화 |
| 공개 공식 · 재등장 주기 | 공개 분석식 | 번호별 과거 등장 간격 중앙값과 현재 미출현 간격 비교 |
| 공개 공식 · 균형 필터 | 공개 분석식 | 번호합·홀짝·저고·번호대·전체 범위의 조합 형태 |
| 공개 공식 · 델타 시스템 | 공개 분석식 | 오름차순 인접 번호 차이값, 반복, 최대 간격, 범위 |
| 공개 공식 · 이월수 | 공개 분석식 | 직전 회차에서 1~2개 번호가 다시 나오는 형태 + 전이 |
| **공개 공식 · 종합 앙상블** | **추천 공개 분석식** | 빈도·최근성·수축·간격·동반출현·균형·델타·이월수 합의 점수 |
| **명리 권장 · 일진 오행·하도 수리** | **전통 명리 권장** | 다음 추첨일 60갑자 일진 + 하도 수리오행 + 오행·음양 균형 |

기본 선택은 기존 호환성을 유지해 **위상잔차 그래프, 전이·간격 위상, 가중 빈도, 동반출현쌍, 종합 앙상블, 명리 권장**입니다.

설치 후 `추천 방식 안내` 센서의 `methods` 속성에서 16개 방식의 상세 설명을 모두 볼 수 있습니다. 개별 추천 센서에도 `method_description`, `core_reason`, 점수 구성, 번호합, 미출현 간격, 동반출현 연결 등 근거가 표시됩니다.

## 즉시 새로고침 · 번호 재생성

버튼 또는 서비스:

```yaml
action: lotto_645.refresh
```

실행하면 다음 순서로 동작합니다.

1. 공유 이력 미러를 확인합니다.
2. 새 공식 회차가 있으면 데이터를 갱신합니다.
3. 선택된 모든 **비AI 추천 방식**을 해당 방식의 고득점 후보군에서 다른 조합으로 재생성합니다.
4. 과거 1등과 완전히 동일한 6개 조합은 계속 제외합니다.
5. 기존 **Home Assistant AI 추천은 변경하지 않습니다.**

같은 이력에서 무작위로 아무 번호나 뽑는 것이 아니라 각 방식의 상위 후보군 안에서 재생성 순번에 따라 다른 후보를 선택합니다.

## 명리 권장

개인 생년월일을 요구하지 않고 **다음 추첨일 자체의 일진(日辰)**을 사용합니다.

- 60갑자 일진의 일간(日干/Day Master)·지지 오행
- 하도(河圖) 수리오행: `1·6 수 / 2·7 화 / 3·8 목 / 4·9 금 / 5·0 토`
- 오행 상생·동기 관계
- 오행 분산과 음양 균형
- 통계 그래프·전이·간격을 보조 점수로 결합

전통 계산 규칙의 재현성을 사용한 문화적 휴리스틱이며 로또 예측 효과가 과학적으로 입증됐다는 의미는 아닙니다.

## Home Assistant AI 추천

통합이 외부 AI API를 직접 호출하지 않고 Home Assistant의 **AI Task 데이터 생성 기능**을 사용합니다.

1. **설정 → AI**에서 데이터 생성 작업 제공자를 선택합니다.
2. 통합 **구성**에서 `Home Assistant AI 추천 사용`을 켭니다.
3. AI Task 엔티티를 비우면 Home Assistant의 기본 데이터 생성 AI를 사용합니다.
4. `AI 추천 생성` 버튼 또는 서비스를 실행합니다.

```yaml
action: lotto_645.generate_ai_recommendation
```

특정 AI Task 지정:

```yaml
action: lotto_645.generate_ai_recommendation
data:
  entity_id: ai_task.google_ai_task
```

AI 결과는 1~45 정수 6개, 중복 여부, 과거 1등 완전일치, 로컬 추천 완전복제, 근거 존재 여부를 로컬에서 다시 검증합니다.
