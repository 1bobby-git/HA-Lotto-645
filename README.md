# 로또 6/45

Home Assistant에서 번호를 생성하고, 구매한 복권과 추첨 결과를 관리합니다.

## 처음 연결할 때

통합을 추가하면 `https://lotto.formulab.kr`에 설치별 고유 자격정보를 만들어 자동 연결합니다. Lotto Lab 계정 로그인, 승인 코드, API 주소·토큰 입력은 필요하지 않습니다.

기존 `lottolab.toiss.kr` 연결은 현재 도메인으로 자동 이동합니다. 이전 회원 승인 방식으로 저장된 연결도 로컬 복권·추천·리뷰와 요청 원장을 보존한 채 자동 연결 방식으로 전환합니다.

연결이 일시적으로 실패하면 저장된 번호와 복권은 그대로 유지하며, 같은 설치 ID와 자격정보로 제한적으로 다시 연결합니다. 공통 비밀키나 비공개 Core는 HA 릴리스에 포함하지 않습니다.

## 한눈에

최근 발표된 당첨번호와 내 복권을 확인합니다. 생성한 번호는 추천 리뷰 메뉴에 모아 표시합니다.

## 추천 리뷰

**현재 생성번호**는 컴포넌트가 현재 선택된 공식으로 가장 최근에 생성한 번호입니다. 새로 생성하면 바뀔 수 있습니다. 공식마다 여러 장을 생성하도록 설정하면 이 값은 그 공식의 첫 번째 게임이며, 나머지 게임은 같은 센서의 `games` 속성에 `numbers`로 들어 있습니다. 센서 개수는 공식 개수 그대로 유지되므로 자동화나 대시보드는 기존 `state`와 `numbers`를 그대로 사용하면 됩니다.

**리뷰 추적번호**는 추첨 전에 저장된 공식 생성번호입니다. 같은 회차의 당첨번호가 발표되면 자동으로 비교하며, 결과 발표 전에는 점수·순위·당첨 여부를 매기지 않습니다. 선택 해제한 공식의 기록도 삭제하지 않습니다.

과거 성적과 누적 별점은 다음 회차 당첨 가능성을 보장하지 않습니다.

## 내 복권

QR을 사진이나 카메라로 읽거나 번호를 직접 입력할 수 있습니다. 확인 후 저장하며 같은 회차의 여러 장을 구분해 수정·삭제·내보내기할 수 있습니다. **복권 추첨 대기**는 구매 후 등록한 복권 번호에 아직 해당 회차 결과가 발표되지 않았다는 뜻입니다.

저장하는 복권 번호가 그 시점의 **현재 생성번호와 6개 모두 정확히 일치**하면, 해당 복권 게임에 생성 공식·생성 시각·생성 ID·Core 버전을 함께 고정 기록합니다. 이후 같은 공식으로 새 번호를 생성해도 구매 당시 연결은 바뀌거나 사라지지 않으며, 해당 회차 결과 발표 후 `내 복권`의 상세 리뷰에서 계속 대조합니다. 구매 복권 추적 결과는 `추천 리뷰`의 공식 누적 별점에 포함하지 않습니다.

QR 사진과 구매번호는 외부 계산 서비스로 전송하지 않습니다. 화면의 등록 기록은 실제 구매·소유권·당첨금 지급 인증이 아니므로 원본 복권을 보관하세요.

## 설정

추천 공식, 선택적 AI 설명, 개인화에 필요한 정보와 구매번호를 관리합니다. 서비스 연결은 통합이 자동 관리하며 별도 계정 메뉴를 표시하지 않습니다. 출생정보는 별도 동의가 있을 때만 개인화 계산에 사용합니다.

`구성 > 추첨 공식`에서 공식을 고른 다음 이어지는 **공식별 생성 게임 수** 화면에서 공식마다 생성할 장수(1~10)를 정합니다. 요청한 장수만큼 **별도 센서**가 만들어지고 이름은 `1번 | 공식명`, `2번 | 공식명` 형식이며, 각 센서의 state가 그 게임의 6개 번호입니다. 한 공식의 전체 게임은 각 센서의 `games` 속성에도 함께 남습니다. 사용량 제한 등으로 장수가 부족하면 이미 확인된 번호는 유지하고 부족한 만큼만 다시 요청하며, `game_shortfall` 속성에 남은 장수가 표시됩니다.

연결이 끊겨도 저장된 번호와 복권은 유지합니다. 새 번호 생성은 연결을 복구한 뒤 이용할 수 있습니다.

## 2.4.13 현재 생성된 번호에서 복권 등록

로또 페이지의 **현재 생성된 번호** 표에 공식·게임마다 `복권 등록` 버튼이 생겼습니다. 번호를 손으로 옮겨 적지 않고 그 자리에서 바로 등록합니다.

- 산 게임의 행에서 `복권 등록`을 누르면 그 번호가 `내 복권`의 **빈 A~E 슬롯**에 들어갑니다. 5줄이 꽉 차면 새 복권을 만들어 이어 붙습니다
- 등록하면 2.4.11의 공식 표식(`적용 공식 · 3번 핫넘버`)이 자동으로 붙습니다
- 이미 등록한 번호의 행은 `등록됨`으로 바뀌어 다시 넣지 않습니다
- 등록 결과(몇 번 줄에 들어갔는지, 새 복권 수)는 안내 문구로 알려줍니다
- 저장에 실패하면 기존 구매번호는 그대로 유지됩니다

> 2.4.12에서 버튼 엔티티로 먼저 제공했던 등록 기능은 이 패널 동작으로 대체했습니다.

## 2.4.11 구매 복권의 공식 표식(어느 게임인지)

생성한 번호를 그대로 산 복권에는 그 번호를 만든 공식 표식이 붙습니다. 이제 **몇 번째 게임인지**까지 표시됩니다.

- 로또 페이지 배지가 `적용 공식 · 핫넘버` → **`적용 공식 · 3번 핫넘버`**로 바뀝니다(센서 이름 `3번 | 핫넘버`와 같은 순서)
- `내 구매번호` 센서의 `formula_links`에 `formula_game`이, 게임별로 `applied_formula_games`가 추가됩니다
- **추첨한 뒤에 등록했거나 과거 회차 등록이어도** 표식이 남습니다. 회차마다 생성된 게임 전체를 원장에 보관하므로 2~5장으로 산 경우도 공식이 연결됩니다
- 리뷰 원장은 **공식당 회차당 1표 원칙 그대로**입니다. 전체 게임 보관과 리뷰 집계는 별개라 공식 간 비교가 왜곡되지 않습니다
- 2.4.11 이전 회차처럼 게임 전체 기록이 없는 경우는 1장만 연결됩니다. 없는 정보는 만들어 내지 않습니다
- 생성 시각을 확인할 수 없는 번호에는 표식을 붙이지 않습니다

## 2.4.10 공식별 게임 개별 센서

공식에 설정한 게임 수(1~10)만큼 **별도 센서**가 만들어집니다. 이름은 `1번 | 공식명`,
`2번 | 공식명` 형식이고 각 센서의 state가 그 게임의 6개 번호입니다.

- **1번 게임은 기존 센서의 entity_id·이력을 그대로 사용**하므로 기존 자동화와 대시보드가 깨지지 않습니다. 2번부터는 `_g2` 같은 새 엔티티가 추가됩니다.
- **센서 이름의 리뷰 표시(☆평가대기, ★4.2 · 84.0점)를 제거**했습니다. 리뷰는 로또 페이지와 각 센서의 `local_review` 속성에서 확인하세요.
- `games`·`game_count` 속성은 그대로 남아 있어 한 공식의 전체 게임을 템플릿에서 읽을 수 있습니다.
- `✓구매일치` 표시와 `purchase_match` 속성은 이제 **그 게임 기준**입니다. 다른 게임의 일치 여부는 해당 게임 센서에서 확인하세요.
- 공식별 생성 게임 수를 줄이면 더 이상 필요 없는 게임 센서의 등록정보가 자동으로 정리됩니다.
- 리뷰 원장은 공식당 회차당 1표 원칙을 그대로 유지합니다.

## 2.4.9 공식별 생성 게임 수 입력 거부 오류 수정

2.4.8에서 **공식별 생성 게임 수** 화면에 1~10 사이의 값을 넣어도 `공식별 생성 게임 수는 1 이상 10 이하여야 합니다`가 뜨고 저장이 되 않았습니다. Home Assistant가 숫자 선택 값을 정수·실수·문자열 중 하나로 넘겨 오는데, 정수만 통과시키는 잘못된 검사가 실제 입력을 모두 거부했습니다. **2.4.8을 쓰셨다면 이 버전으로 업데이트하세요.** 설정 데이터와 구매번호·리뷰 기록은 그대로 유지됩니다.

- 숫자 선택 값을 정수·실수(`5.0`)·문자열(`5`, `5.0`, 공백 포함) 모두 정수로 정규화한 뒤 1~10 범위를 검사합니다
- 정수 변환과 범위 검사를 분리해, 범위 밖 값은 저장값만 1장으로 되돌리고 나머지 공식 값은 유지합니다
- 값 하나가 잘못돼도 나머지 공식의 장수는 보존됩니다
- 실제 프론트엔드가 보내는 형태(int·float·str)를 그대로 피xture로 넣어 회귀를 고정했습니다. 엄격한 정수 검사 상태로 되돌리면 이 테스트가 실제로 실패합니다

## 2.4.8 공식별 생성 게임 수 설정 오류 수정

2.4.7에서 `NameError: name 'normalize_counts' is not defined`으로 통합 설정에 실패할 수 있었습니다. 공식별 생성 수를 읽는 데 필요한 모듈 import가 배포본에 누락된 문제입니다. **2.4.7로 업그레이드하고 설정이 실패했다면 이 버전으로 업데이트하세요.** 설정 데이터와 구매번호·리뷰 기록은 삭제되지 않으므로 다시 입력할 필요가 없습니다.

원인은 검증을 통과한 테스트만으로는 이 결함을 찾을 수 없는 구조였습니다. 통합 대부분의 모듈은 Home Assistant를 import해야 해서 테스트가 직접 불러오지 못하고, 문법 검사(`compileall`)는 이름이 연결됐는지를 확인하지 않기 때문입니다.

- 누락된 import 복구
- `tests/test_module_imports.py` 추가: 어떤 모듈도 형제 모듈의 helper를 import하지 않은 채 호출하지 못하도록 검사합니다. 이미 import한 모듈뿐 아니라 **아예 import 문이 빠진 경우**도 잡습니다
- 이 검사는 회귀를 실제로 잡아냅니다. import를 지우면 실패하고 되돌리면 통과합니다

## 2.4.7 공식별 생성 게임 수

> **2.4.10 변경:** 공식당 하나의 센서에 `games` 속성을 담던 방식은 게임 수만큼 별도 센서(`N번 | 공식명`)로 바뀌었습니다. 자세한 내용은 2.4.10 항목을 보세요. 아래 내용은 2.4.7 당시의 동작입니다.

`구성 > 추첨 공식`에서 공식을 고른 다음 이어지는 **공식별 생성 게임 수** 화면에서 공식마다 1~10개를 지정할 수 있습니다. 센서는 공식마다 하나만 그대로 유지되고, 센서 개수를 늘리지 않습니다. 기존 자동화와 대시보드는 `state`와 `numbers`(첫 번째 게임)를 그대로 쓰면 되고, 나머지 게임은 같은 센서의 `games` 속성에 담깁니다.

`games`에는 게임별로 `numbers`, `core_reason`, `generated_at`, `formula_game`, `purchase_match`가 들어 있으며, `game_count`과 `requested_game_count`로 실제 장수와 요청 장수를 확인할 수 있습니다. 어느 공식의 게임이든 저장한 복권 6개와 모두 일치하면 센서 이름과 아이콘에 `✓구매일치`가 표시됩니다.

부족한 장수가 생기면(서비스 사용량 제한, 중간 응답 실패 등) 이미 확인된 번호는 유지하고 부족한 것만 다음 갱신에서 다시 요청합니다. 남은 장수는 `game_shortfall` 속성과 `추천 요약` 센서에서 확인할 수 있습니다. 어떤 공식도 1등 확률을 바꾸지 않으며 공식당 여러 장을 뽑아도 당첨 확률은 동일합니다.

리뷰 별점(★)은 회차당 공식 1표 원칙을 그대로 유지합니다. 공식이 5장으로 설정되어도 1표만 반영되므로 공식 간 비교가 왜곡되지 않습니다.

## 2.4.6 Lotto Lab 연결 상태 확인 · 계정 연결 자동 완료

기기의 진단 항목에 **Lotto Lab 연결**(연결됨/연결 끊김)을 추가했습니다. 5분마다 이 기기의 인증 정보로 Lotto Lab 서비스에 상태 확인 요청을 보내며, 속성에서 연결 방식(`회원 계정 연결` 또는 `자동 연결 (계정 미연결)`), 마지막 오류, 상태가 바뀐 시각, 서비스 최신 회차를 확인할 수 있습니다. 인증이 만료되었거나 거부되면 자동으로 다시 연결합니다.

`구성 > Lotto Lab 계정 연결`에서 표시된 코드로 웹에서 연결을 승인하면, 이제 Home Assistant가 백그라운드에서 승인을 확인해 연결을 자동으로 완료합니다. HA로 돌아가 다시 제출하지 않아도 되며, 연결이 끝나면 통합이 다시 로드되어 연결 방식이 `회원 계정 연결`로 바뀝니다.

## 2.4.5 번호 생성 자동 복구

서버 재시작 등으로 번호 생성 요청이 실패·취소되면 이전에는 같은 요청을 다시 보내지 않아, `즉시 새로고침 · 번호 재생성`을 누르기 전까지 `추천 요약`이 `0게임`에 머물고 공식별 센서가 `사용할 수 없음`으로 남았습니다. 이제 실패한 요청을 10분 뒤부터 간격을 늘려(최대 6시간) 자동으로 다시 요청하며, 업데이트 전에 남아 있던 실패 기록은 업데이트 후 첫 갱신에서 바로 다시 요청합니다. 서버가 더 이상 알지 못하는 대기 작업은 정리한 뒤 새로 요청하고, 생성 대기·복구 상태도 5분마다 다시 확인합니다. 실패한 요청은 서버의 일일 생성 한도에 포함되지 않습니다.

## 2.4.4 내 복권 로또 용지 디자인

`내 복권`에 등록한 복권을 실제 로또 6/45 용지처럼 표시합니다. 민트 배경 위 흰 용지에 물결 모양 상단, 분홍 세로 띠와 옅은 LOTTO 워터마크, 점선 구분선을 적용했고 번호는 공 색상 대신 두 자리 검은 인쇄 숫자(예: `08`)로 보여줍니다. 추첨 후 당첨번호와 일치한 번호는 펜으로 표시한 듯한 분홍 동그라미, 보너스 일치는 파란 점선 동그라미로 표시하며 게임별 결과(`미당첨`, `5등`, `추첨 대기`)는 게임 기호 옆에 둡니다. 용지에는 등록일·추첨일·게임 수를 표시하며, QR과 바코드는 장식용으로 실제 복권 정보가 아닙니다. 다크 테마에서도 용지와 번호 색은 그대로 유지하고, 결과 요약과 수정·삭제 버튼은 용지 아래에 둡니다. 복권 등록 창의 QR 스캔 아이콘이 일부만 그려지던 문제도 수정했습니다.

## 2.3.3 한눈에 간격 압축 · 등록 복권 요약

`한눈에`의 주요 영역 사이 상하 간격을 줄이고 우측 `추천 리뷰`와 `MY LOTTO` 배너 사이의 불필요한 여백을 제거했습니다. 다가오는 회차의 `복권 등록` 버튼 옆에는 이미 등록된 복권이 있을 때 `등록 복권 N장 · M게임`과 복권별 게임 수를 간단히 표시합니다. 기존 우측의 중복 내 복권 상태 카드는 제거해 정보 밀도를 높였습니다.

## 2.3.2 MY LOTTO 간편 등록 배너 복원

`한눈에`의 우측 사이드 하단에 기존 MY LOTTO 티켓 그래픽 배너를 그대로 복원했습니다. `종이 복권은 그대로, 번호만 간편하게.` 안내와 `QR로 가져오기` 버튼을 유지하며 기존 복권 등록 화면으로 연결됩니다.

## 2.3.1 한눈에 단순화 · 구매 복권 공식 자동 연결

같은 회차의 공식 생성번호와 구매 복권 번호 6개가 정확히 일치하면 해당 게임에 공식을 자동 연결하고 `적용 공식 · 공식명`으로 표시합니다. `한눈에`의 중복 카운트다운과 중복 등록 요소를 제거하고, 다가오는 회차 카드 하나에 추첨 일정과 주요 상태를 모았습니다. 좁은 화면에서는 복권 게임 상태·공식 배지·도구 모음이 아래로 재배치되어 320px 이상에서 가로 침범이 발생하지 않도록 반응형 구조를 보강했습니다.

## 2.3.0 3탭 정보 구조 개편

`한눈에`는 다가오는 회차와 남은 시간을 가장 먼저 보여주고, 지난 회차 결과는 그 아래로 분리합니다. `내 복권`은 실제 구매 복권을 장별 카드·스와이프로 관리하며 A~E 최대 5게임과 추첨 후 상세 결과, 저장 당시 연결 공식을 확인할 수 있습니다. `추천 리뷰`는 구매 복권을 제외하고 컴포넌트가 생성한 공식 번호만 평가하며, 지난 회차 점수·순위와 누적 공식 순위·필터·최근 성적을 제공합니다.

## 2.2.5 내 복권 5게임 · 스와이프

홈의 `내 복권` 카드에서 한 장에 저장된 A~E 최대 5게임을 모두 표시합니다. 같은 회차에 복권이 여러 장 등록되어 있으면 카드 단위로 좌우 스와이프할 수 있고, 데스크톱에서는 이전/다음 버튼과 페이지 표시로 이동할 수 있습니다.

## 2.2.4 구매 복권 · 생성 공식 영구 연결

현재 생성번호와 정확히 같은 번호를 구매 복권으로 저장하면 그 시점의 생성 공식을 복권 게임에 고정 연결합니다. 새 번호를 다시 생성해도 이전 구매 복권의 공식·생성 기록은 유지되며, 같은 회차 당첨 결과가 발표되면 구매추적 결과로 계속 표시합니다. 기존 v1/v2 구매 저장 형식은 그대로 읽고 새 저장부터 v3 형식으로 확장합니다. 기존 복권도 같은 회차의 추첨 전 리뷰 저장소에 정확히 같은 번호와 공식 기록이 남아 있을 때만 증거 기반으로 연결하며, 기록이 없으면 공식을 추정하지 않습니다.

## 2.2.3 고급 공식 선택 복구

고급 선택 셀렉터에 균등 알고리즘 5종과 빈도 프리셋 2종을 다시 표시합니다. 기존 저장 선택값은 유지되며 기본 공식 목록과 중복 표시하지 않습니다.

같은 회차에 저장한 실제 구매번호와 공식·AI 생성번호 6개가 모두 같으면 Home Assistant 센서와 로또 복권 화면에 구매일치 상태를 표시합니다. 부분 일치는 표시하지 않으며 실제 구매 사실을 인증하는 기능은 아닙니다.
